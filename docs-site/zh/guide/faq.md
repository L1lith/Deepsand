# 常见问题

## DeepCode 是否看到我的主目录？

不会。沙箱会看到位于 `/workspace` 的项目目录以及您明确授予的目录。主机文件系统的其余部分未安装。

## 当我批准目录请求时会发生什么？

Deepsand 将目录添加为授权，重新创建附加了新挂载的容器，并恢复 DeepCode 会话。正在运行的沙箱在不重新创建的情况下无法获得绑定安装。

## 我的对话存储在哪里？

对话历史记录、会话、附件和生成的技能位于每个项目的 Docker 卷中。磁盘上的项目文件夹仅包含您的代码和文件。

从 Deepsand 中删除项目不会删除该卷。擦除项目的 DeepCode 数据会删除该卷，但不会影响项目文件夹。

## API 密钥和秘密存储在哪里？

秘密使用操作系统密钥库保存的密钥进行静态加密，并且仅在沙箱启动时作为环境变量注入沙箱中。界面显示名称和长度，而不显示存储的值。

凭证也可以从主机 DeepCode 配置继承。它们不会复制到项目文件夹中。

## 每个项目可以使用不同的模型吗？

是的。项目可以继承主机配置或覆盖其自己的设置中的模型、基本 URL 和凭据。标头选择器还可以为项目选择一个模型； **遵循配置** 表示该项目没有 pin 1。

## 我应该使用哪种模型来降低成本？

对于大多数任务，请使用闪存模型。 Deepsand 默认为 `deepseek-v4-flash`，这是日常编码、解释和编辑的更便宜的选择。保留 `deepseek-v4-pro` 用于闪存明显遇到困难或需要其额外功能的工作，因为专业型号的运行成本更高。

从项目标题或使用 DeepCode 终端中的 `/model` 切换模型。如果您是第一次尝试 Deepsand，请从 Flash 开始，只有当您有需要它的任务时才转到专业版。

## 思维滑块有什么作用？

思考滑块位于项目标题中模型选择器的旁边。它控制模型在回答之前进行多少推理。

|停止|这意味着什么 |
| --- | --- |
| **离开** |回答之前不要思考。最快，但最不小心。 |
| **快的** |一点思考，进行小的、明确的编辑。 |
| **均衡** |适度的思考。中间的停止点和实际工作的合理默认值。 |
| **深的** |像模型一样努力思考。最慢也最贵。 |
| **默认** |服从主机`settings.json`；如果它什么也没说，DeepCode 就会回到平衡状态。 |

对于大多数任务，将滑块保持在 **均衡** 上。这是中间设置，它可以提供良好的结果，而无需为每个请求进行最慢、最昂贵的推理。仅针对真正困难的问题才转向 **深的**，并使用 **离开** 或 **快的** 进行小型、可预测的编辑。

## Deepsand 只能与 DeepSeek 配合使用吗？

否。DeepSeek 是默认值，因为它是 Deepsand 附带的模型和端点，但 Deepsand 使用模型名称、基本 URL 和 API 密钥配置 DeepCode CLI。您可以将其指向公开 CLI 可以调用的 API 的另一个提供程序，通常是 OpenAI 兼容端点。

在 **设置** 或项目自己的凭据中设置提供程序的基本 URL 和模型，并将该提供程序的 API 密钥存储在同一位置。沙箱的网络策略还必须允许提供商的端点。

## 如果 Docker Desktop 未运行或停止响应怎么办？

如果没有 Docker 引擎，Deepsand 无法启动沙箱。如果 Docker Desktop 未运行，请将其启动并等待发动机完成启动。 Deepsand 重新检查窗口何时重新获得焦点，并且状态条提供重试。

有时 Docker Desktop 仍在运行，但其引擎已停止响应。重新启动 Deepsand 并不能解决这个问题； Docker Desktop本身需要重新启动。

- **当应用程序内控件出现时，请使用它。** 如果Deepsand检测到Docker Desktop，则在状态条或终端警告中显示**重启Docker Desktop…**。该控件重新启动 Docker 引擎，包括它在 Windows 上使用的 WSL 进程，并等待容器可以再次启动。
- **Windows:** 右键单击​​通知区域中的 Docker 鲸鱼，然后选择 **重新启动**。如果缺少该选项，请打开 Docker Desktop，选择 **故障排除**，然后选择 **重启Docker Desktop**。
- **macOS:** 单击菜单栏中的 Docker 鲸鱼并选择 **重新启动**。
- **Linux:** 打开Docker Desktop菜单，选择**故障排除**，然后选择**重启Docker Desktop**。如果您使用 Docker Engine 而不是 Docker Desktop，请重新启动其服务，例如 `sudo systemctl restart docker`。

重启Docker Desktop会结束机器上的所有容器，包括与Deepsand无关的容器。 Deepsand 提供重新启动，但不会自动执行。请参阅 [Docker的故障排除文档](https://docs.docker.com/desktop/troubleshoot-and-support/troubleshoot/) 了解特定于平台的菜单。

## 我可以在没有互联网连接的情况下使用Deepsand吗？

该模型需要它的端点。使用 `none` 网络模式，只有该端点可通过 Deepsand 代理访问。除非您允许它们所需的主机，否则软件包安装和其他网络访问将会失败。

## 如何更新Deepsand？

打开 **设置**，然后打开 **更新**，然后检查是否有更新版本。发布版本会下载签名的更新并在安装更新后重新启动应用程序。安装更新会停止运行沙箱。

## 有命令行界面吗？

是的。 `deepsandctl` 提供无头命令，例如 `doctor`、`plan`、`run`、`watch`、`requests` 和 `network`。桌面应用程序和 CLI 在 `deepsand-core` 中共享相同的策略代码。

## 如何报告安全问题？

不要针对安全问题公开发布问题。通过存储库的安全报告渠道私下联系维护人员，并提供足够的详细信息来重现问题。
