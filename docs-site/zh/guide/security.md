# 沙箱如何工作

简而言之：助手可以在您选择的项目和您批准的文件夹中工作，而不能在计算机上的其他地方工作。

Deepsand 的承诺是狭窄且可测试的：沙箱可以到达项目目录和您明确授予的目录，除此之外别无其他。

## 边界

除了选择的绑定挂载 Deepsand 之外，容器没有主机文件系统的视图。容器的挂载命名空间内不存在其他主机路径，因此没有可转义的主机文件。

这里描述的其他所有内容都是在该边界之上的纵深防御。

## 强制执行什么

- 仅从主机安装工作区和显式授权。
- 响应假脱机和状态目录以只读方式安装。
- 容器运行时套接字按名称拒绝。
- 容器根文件系统是只读的，临时文件系统的大小为 `/tmp` 和 `/run`。
- 符号链接在检查路径之前解析，因此链接无法隐藏禁止的目标。
- 在 DeepCode 运行之前特权被删除，并且 `no-new-privileges` 阻止它们被重新获得。

## 网络模式

|模式|它允许什么 |
| --- | --- |
|无 |仅通过 Deepsand 代理的模型端点。 |
|列入白名单 |模型端点、代理以及白名单上的主机或地址。 |
|互联网|互联网访问，本地和私有范围被阻止在容器内。 |
|完整|不受本地网络限制的互联网访问。仅当沙箱真正需要您的本地网络时才使用它。 |

列入许可名单的主机名通过代理，代理自行解析名称并拒绝私有地址空间中的结果。容器规则直接允许列入白名单的地址，因为数据库客户端或其他非 HTTP 程序无法使用代理。条目中指定的端口也会在主机的环回上发布，而不是在每个接口上发布。

## 你决定什么

Deepsand 从不自动授予访问权限。请求会通过其所请求的路径、主机、工具或资源到达您，并且沙箱将保持暂停状态，直到您做出决定。

对沙箱已有的内容的请求会被拒绝并给出解释，因为自动允许将意味着您从未给予过同意。任何模棱两可的事情都会传到你身上。

## 它不能防止什么

- 模型提供者可以看到您发送给它的内容。
- 您放置在工作区中的文件对沙箱可见，并且可能会被更改或删除。
- 格式错误的工具或模型指令仍然可以请求访问。决定权仍由您决定。
- Docker 本身在边界之外。保持 Docker Desktop 和主机操作系统更新。
