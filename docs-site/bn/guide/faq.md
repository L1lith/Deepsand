# প্রায়শই জিজ্ঞাসিত প্রশ্ন

## DeepCode কি আমার হোম ডিরেক্টরি দেখতে পায়?

না। স্যান্ডবক্স `/workspace`-এ প্রোজেক্ট ডিরেক্টরি এবং আপনি স্পষ্টভাবে মঞ্জুর করা ডিরেক্টরিগুলি দেখে। বাকি হোস্ট ফাইল সিস্টেম মাউন্ট করা হয় না।

## যখন আমি একটি ডিরেক্টরি অনুরোধ অনুমোদন করি তখন কি হবে?

Deepsand একটি অনুদান হিসাবে ডিরেক্টরি যোগ করে, নতুন মাউন্ট সংযুক্ত করে ধারকটি পুনরায় তৈরি করে এবং DeepCode সেশন পুনরায় শুরু করে। একটি চলমান স্যান্ডবক্স পুনরায় তৈরি না করে একটি বাঁধাই মাউন্ট লাভ করতে পারে না।

## আমার কথোপকথন কোথায় সংরক্ষণ করা হয়?

কথোপকথনের ইতিহাস, সেশন, সংযুক্তি এবং জেনারেট করা দক্ষতা প্রতি-প্রকল্প Docker ভলিউমে থাকে। ডিস্কের প্রোজেক্ট ফোল্ডারে শুধুমাত্র আপনার কোড এবং ফাইল থাকে।

Deepsand থেকে একটি প্রকল্প সরানো সেই ভলিউম মুছে দেয় না। একটি প্রকল্পের DeepCode ডেটা মুছে ফেলার ফলে ভলিউম মুছে যায় কিন্তু প্রোজেক্ট ফোল্ডারটি অস্পর্শিত থাকে।

## API কী এবং গোপনীয়তা কোথায় সংরক্ষণ করা হয়?

অপারেটিং সিস্টেমের কীস্টোরের কাছে থাকা একটি কী দিয়ে গোপনীয়তাগুলি বিশ্রামে এনক্রিপ্ট করা হয় এবং যখন এটি শুরু হয় তখনই পরিবেশের পরিবর্তনশীল হিসাবে স্যান্ডবক্সে প্রবেশ করানো হয়। ইন্টারফেস নাম এবং দৈর্ঘ্য দেখায়, কখনও সঞ্চিত মান নয়।

আপনার হোস্ট DeepCode কনফিগারেশন থেকেও শংসাপত্রগুলি উত্তরাধিকারসূত্রে পাওয়া যেতে পারে। তারা প্রকল্প ফোল্ডারে অনুলিপি করা হয় না.

## প্রতিটি প্রকল্প একটি ভিন্ন মডেল ব্যবহার করতে পারেন?

হ্যাঁ। একটি প্রকল্প হোস্ট কনফিগারেশনের উত্তরাধিকারী হতে পারে বা তার নিজস্ব সেটিংসে মডেল, বেস URL এবং শংসাপত্রগুলিকে ওভাররাইড করতে পারে। শিরোনাম নির্বাচক এছাড়াও প্রকল্পের জন্য একটি মডেল চয়ন করতে পারেন; **কনফিগারেশন বিলম্বিত করুন** মানে প্রকল্পটি একটি পিন করে না।

## খরচ কম রাখতে আমার কোন মডেল ব্যবহার করা উচিত?

বেশিরভাগ কাজের জন্য একটি ফ্ল্যাশ মডেল ব্যবহার করুন। Deepsand ডিফল্ট `deepseek-v4-flash`, যা দৈনন্দিন কোডিং, ব্যাখ্যা এবং সম্পাদনার জন্য সস্তা পছন্দ। `deepseek-v4-pro` কাজের জন্য রিজার্ভ করুন যেখানে ফ্ল্যাশ স্পষ্টভাবে সংগ্রাম করছে বা আপনার এটির অতিরিক্ত ক্ষমতা প্রয়োজন, কারণ প্রো মডেল চালানোর জন্য বেশি খরচ হয়।

প্রকল্প শিরোনাম থেকে বা DeepCode টার্মিনালে `/model` দিয়ে মডেলগুলি স্যুইচ করুন৷ আপনি যদি প্রথমবারের জন্য Deepsand চেষ্টা করে থাকেন, তাহলে ফ্ল্যাশ দিয়ে শুরু করুন এবং শুধুমাত্র যখন আপনার প্রয়োজনের কাজ থাকে তখনই প্রোতে যান।

## চিন্তা স্লাইডার কি করে?

থিংকিং স্লাইডারটি প্রজেক্ট হেডারে মডেল নির্বাচকের পাশে। এটি নিয়ন্ত্রণ করে যে মডেলটি উত্তর দেওয়ার আগে কতটা যুক্তি করে।

| থামো | এর মানে কি |
| --- | --- |
| **বন্ধ** | উত্তর দেওয়ার আগে ভাববেন না। দ্রুততম, কিন্তু সর্বনিম্ন সতর্কতা. |
| **দ্রুত** | একটু চিন্তা, ছোট সুনির্দিষ্ট সম্পাদনা জন্য. |
| **সুষম** | মধ্যপন্থী চিন্তা। মধ্যম স্টপ এবং বাস্তব কাজের জন্য বুদ্ধিমান ডিফল্ট। |
| **গভীর** | মডেল হিসাবে কঠিন হিসাবে চিন্তা করুন. সবচেয়ে ধীর এবং সবচেয়ে ব্যয়বহুল। |
| **ডিফল্ট** | হোস্ট `settings.json` এ বিলম্বিত করুন; যদি এটি কিছু না বলে, DeepCode ব্যালেন্সড-এ ফিরে আসে। |

বেশিরভাগ কাজের জন্য **সুষম**-এ স্লাইডার রাখুন। এটি মধ্যম সেটিং, এবং এটি প্রতিটি অনুরোধে সবচেয়ে ধীর, সবচেয়ে ব্যয়বহুল যুক্তির জন্য অর্থ প্রদান না করেই ভাল ফলাফল দেয়। শুধুমাত্র সত্যিকারের কঠিন সমস্যার জন্য **গভীর** এ যান, এবং ছোট, অনুমানযোগ্য সম্পাদনার জন্য **বন্ধ** বা **দ্রুত** ব্যবহার করুন।

## Deepsand কি শুধুমাত্র DeepSeek এর সাথে কাজ করে?

না। ডিপসিক ডিফল্ট কারণ এটি মডেল এবং এন্ডপয়েন্ট Deepsand এর সাথে শিপ, কিন্তু Deepsand একটি মডেল নাম, বেস URL এবং API কী সহ DeepCode CLI কনফিগার করে। আপনি এটিকে অন্য একটি প্রদানকারীর কাছে নির্দেশ করতে পারেন যা একটি API প্রকাশ করে যেটি CLI কল করতে পারে, সাধারণত একটি OpenAI- সামঞ্জস্যপূর্ণ এন্ডপয়েন্ট।

**সেটিংস**-এ প্রদানকারীর বেস URL এবং মডেল সেট করুন, অথবা একটি প্রকল্পের নিজস্ব শংসাপত্রে, এবং সেই প্রদানকারীর API কী একই জায়গায় সংরক্ষণ করুন৷ স্যান্ডবক্সের নেটওয়ার্ক নীতি অবশ্যই প্রদানকারীর এন্ডপয়েন্টকে অনুমতি দেবে।

## Docker Desktop চলমান না হলে বা সাড়া দেওয়া বন্ধ করে দিলে কী হবে?

Deepsand Docker ইঞ্জিন ছাড়া একটি স্যান্ডবক্স শুরু করতে পারে না। Docker Desktop চলমান না হলে, এটি শুরু করুন এবং ইঞ্জিন শুরু হওয়া শেষ হওয়ার জন্য অপেক্ষা করুন। Deepsand পুনরায় চেক করে যখন উইন্ডোটি ফোকাস ফিরে পায়, এবং স্ট্যাটাস স্ট্রিপ আবার চেষ্টা করার প্রস্তাব দেয়।

কখনও কখনও Docker Desktop এখনও চলছে কিন্তু এর ইঞ্জিন সাড়া দেওয়া বন্ধ করে দিয়েছে। Deepsand পুনরায় আরম্ভ করা এটি ঠিক করে না; Docker Desktop নিজেই আবার চালু করতে হবে।

- **এটি প্রদর্শিত হলে অ্যাপ-মধ্যস্থ নিয়ন্ত্রণ ব্যবহার করুন।** যদি Deepsand Docker Desktop শনাক্ত করে, এটি স্ট্যাটাস স্ট্রিপ বা টার্মিনাল সতর্কতায় **Docker Desktop পুনরায় চালু করুন...** দেখায়। সেই নিয়ন্ত্রণ Docker ইঞ্জিনটিকে পুনরায় চালু করে, এতে WSL প্রক্রিয়াটি Windows-এ ব্যবহার করা হয় এবং একটি কন্টেইনার আবার শুরু না হওয়া পর্যন্ত অপেক্ষা করে।
- **Windows:** বিজ্ঞপ্তি এলাকায় Docker তিমিতে ডান-ক্লিক করুন এবং **রিস্টার্ট করুন** বেছে নিন। যদি সেই বিকল্পটি অনুপস্থিত থাকে, Docker Desktop খুলুন, **সমস্যা সমাধান** নির্বাচন করুন, তারপর **Docker Desktop পুনরায় চালু করুন** নির্বাচন করুন।
- **macOS:** মেনু বারে Docker তিমিতে ক্লিক করুন এবং **রিস্টার্ট করুন** বেছে নিন।
- **Linux:** Docker Desktop মেনু খুলুন, **সমস্যা সমাধান**, তারপর **Docker Desktop পুনরায় চালু করুন** নির্বাচন করুন। আপনি যদি Docker Desktop এর পরিবর্তে Docker Engine ব্যবহার করেন, তাহলে এটির পরিষেবা পুনরায় চালু করুন, উদাহরণস্বরূপ `sudo systemctl restart docker`।

Docker Desktop পুনঃসূচনা করা হলে মেশিনের প্রতিটি কন্টেইনার শেষ হয়ে যায়, যার মধ্যে Deepsand-এর সাথে সম্পর্কহীন কন্টেইনার রয়েছে। Deepsand পুনরায় চালু করার প্রস্তাব দেয় কিন্তু স্বয়ংক্রিয়ভাবে তা করে না। প্ল্যাটফর্ম-নির্দিষ্ট মেনুর জন্য [Docker এর সমস্যা সমাধানের ডকুমেন্টেশন](https://docs.docker.com/desktop/troubleshoot-and-support/troubleshoot/) দেখুন।

## আমি কি ইন্টারনেট অ্যাক্সেস ছাড়া Deepsand ব্যবহার করতে পারি?

মডেলটির শেষ বিন্দু প্রয়োজন। `none` নেটওয়ার্ক মোডের সাথে, শুধুমাত্র সেই শেষ পয়েন্টটি Deepsand প্রক্সির মাধ্যমে পৌঁছানো যায়। প্যাকেজ ইনস্টল এবং অন্যান্য নেটওয়ার্ক অ্যাক্সেস ব্যর্থ হবে যদি না আপনি তাদের প্রয়োজনীয় হোস্টদের অনুমতি দেন।

## আমি কিভাবে Deepsand আপডেট করব?

**সেটিংস** খুলুন, তারপর **আপডেট**, এবং একটি নতুন সংস্করণ পরীক্ষা করুন। রিলিজ ডাউনলোড স্বাক্ষরিত আপডেট তৈরি করে এবং একটি ইনস্টল করার পরে অ্যাপটি পুনরায় চালু করুন। একটি আপডেট ইনস্টল করা স্যান্ডবক্স চালানো বন্ধ করে দেয়।

## একটি কমান্ড লাইন ইন্টারফেস আছে?

হ্যাঁ। `deepsandctl` হেডলেস কমান্ড যেমন `doctor`, `plan`, `run`, `watch`, `requests` এবং `network` প্রদান করে। ডেস্কটপ অ্যাপ এবং CLI `deepsand-core`-এ একই নীতি কোড শেয়ার করে।

## আমি কিভাবে একটি নিরাপত্তা সমস্যা রিপোর্ট করব?

নিরাপত্তা সমস্যার জন্য পাবলিক ইস্যু খুলবেন না। সংগ্রহস্থলের নিরাপত্তা রিপোর্টিং চ্যানেলের মাধ্যমে রক্ষণাবেক্ষণকারীদের সাথে ব্যক্তিগতভাবে যোগাযোগ করুন এবং সমস্যাটি পুনরুত্পাদন করার জন্য যথেষ্ট বিশদ অন্তর্ভুক্ত করুন।
