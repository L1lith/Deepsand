# अक्सर पूछे जाने वाले प्रश्नों

## क्या DeepCode मेरी होम निर्देशिका देखता है?

नहीं, सैंडबॉक्स `/workspace` पर प्रोजेक्ट निर्देशिका और आपके द्वारा स्पष्ट रूप से प्रदान की गई निर्देशिकाओं को देखता है। शेष होस्ट फ़ाइल सिस्टम माउंट नहीं किया गया है.

## जब मैं किसी निर्देशिका अनुरोध को स्वीकृत करता हूँ तो क्या होता है?

Deepsand निर्देशिका को अनुदान के रूप में जोड़ता है, नए माउंट संलग्न के साथ कंटेनर को फिर से बनाता है, और DeepCode सत्र फिर से शुरू करता है। एक चालू सैंडबॉक्स पुनः बनाए बिना बाइंड माउंट हासिल नहीं कर सकता।

## मेरी बातचीत कहाँ संग्रहीत हैं?

वार्तालाप इतिहास, सत्र, अनुलग्नक और उत्पन्न कौशल प्रति-प्रोजेक्ट Docker वॉल्यूम में रहते हैं। डिस्क पर प्रोजेक्ट फ़ोल्डर में केवल आपका कोड और फ़ाइलें हैं।

Deepsand से किसी प्रोजेक्ट को हटाने से वह वॉल्यूम नहीं हटता। किसी प्रोजेक्ट के DeepCode डेटा को पोंछने से वॉल्यूम हट जाता है लेकिन प्रोजेक्ट फ़ोल्डर अछूता रह जाता है।

## API कुंजियाँ और रहस्य कहाँ संग्रहीत हैं?

रहस्यों को ऑपरेटिंग सिस्टम के कीस्टोर द्वारा रखी गई एक कुंजी के साथ एन्क्रिप्ट किया जाता है, और इसे शुरू होने पर ही पर्यावरण चर के रूप में सैंडबॉक्स में इंजेक्ट किया जाता है। इंटरफ़ेस नाम और लंबाई दिखाता है, संग्रहीत मान कभी नहीं।

क्रेडेंशियल आपके होस्ट DeepCode कॉन्फ़िगरेशन से भी प्राप्त किए जा सकते हैं। उन्हें प्रोजेक्ट फ़ोल्डर में कॉपी नहीं किया गया है.

## क्या प्रत्येक प्रोजेक्ट एक अलग मॉडल का उपयोग कर सकता है?

हाँ। एक प्रोजेक्ट होस्ट कॉन्फ़िगरेशन को इनहेरिट कर सकता है या अपनी सेटिंग्स में मॉडल, बेस यूआरएल और क्रेडेंशियल्स को ओवरराइड कर सकता है। हेडर चयनकर्ता प्रोजेक्ट के लिए एक मॉडल भी चुन सकता है; **कॉन्फ़िगरेशन को स्थगित करें** का अर्थ है कि प्रोजेक्ट किसी को पिन नहीं करता है।

## लागत कम रखने के लिए मुझे किस मॉडल का उपयोग करना चाहिए?

अधिकांश कार्यों के लिए फ़्लैश मॉडल का उपयोग करें. Deepsand डिफ़ॉल्ट रूप से `deepseek-v4-flash` है, जो रोजमर्रा की कोडिंग, स्पष्टीकरण और संपादन के लिए सबसे सस्ता विकल्प है। `deepseek-v4-pro` को उस काम के लिए आरक्षित करें जहां फ्लैश स्पष्ट रूप से संघर्ष कर रहा है या आपको इसकी अतिरिक्त क्षमता की आवश्यकता है, क्योंकि प्रो मॉडल को चलाने में अधिक लागत आती है।

प्रोजेक्ट हेडर से या DeepCode टर्मिनल में `/model` के साथ मॉडल स्विच करें। यदि आप पहली बार Deepsand आज़मा रहे हैं, तो फ़्लैश से शुरुआत करें और केवल तभी प्रो पर जाएँ जब आपके पास कोई ऐसा कार्य हो जिसके लिए इसकी आवश्यकता हो।

## थिंकिंग स्लाइडर क्या करता है?

थिंकिंग स्लाइडर प्रोजेक्ट हेडर में मॉडल चयनकर्ता के बगल में है। यह नियंत्रित करता है कि मॉडल उत्तर देने से पहले कितना तर्क करता है।

| रुकें | इसका क्या मतलब है |
| --- | --- |
| **बंद** | उत्तर देने से पहले मत सोचो. सबसे तेज़, लेकिन सबसे कम सावधान। |
| **जल्दी** | छोटे-छोटे सुस्पष्ट संपादनों के लिए थोड़ी सोच। |
| **संतुलित** | मध्यम सोच. वास्तविक कार्य के लिए मध्य पड़ाव और समझदार डिफ़ॉल्ट। |
| **गहरा** | मॉडल जितना सोच सके उतना कठिन सोचें। सबसे धीमा और सबसे महंगा. |
| **गलती करना** | मेजबान `settings.json` को स्थगित करें; यदि यह कुछ नहीं कहता है, तो DeepCode वापस Balanced पर आ जाता है। |

अधिकांश कार्यों के लिए स्लाइडर को **संतुलित** पर रखें। यह मध्य सेटिंग है, और यह हर अनुरोध पर सबसे धीमे, सबसे महंगे तर्क के लिए भुगतान किए बिना अच्छे परिणाम देता है। केवल वास्तव में कठिन समस्याओं के लिए **गहरा** पर जाएँ, और छोटे, पूर्वानुमानित संपादनों के लिए **बंद** या **जल्दी** का उपयोग करें।

## क्या Deepsand केवल डीपसीक के साथ काम करता है?

नहीं, डीपसीक डिफ़ॉल्ट है क्योंकि यह मॉडल और एंडपॉइंट Deepsand जहाजों के साथ है, लेकिन Deepsand DeepCode CLI को मॉडल नाम, बेस यूआरएल और API कुंजी के साथ कॉन्फ़िगर करता है। आप इसे किसी अन्य प्रदाता पर इंगित कर सकते हैं जो API को उजागर करता है जिसे CLI कॉल कर सकता है, आमतौर पर एक OpenAI-संगत समापन बिंदु।

प्रदाता के आधार URL और मॉडल को **सेटिंग्स** में, या किसी प्रोजेक्ट के स्वयं के क्रेडेंशियल में सेट करें, और उस प्रदाता की API कुंजी को उसी स्थान पर संग्रहीत करें। सैंडबॉक्स की नेटवर्क नीति को प्रदाता के समापन बिंदु की भी अनुमति देनी चाहिए।

## यदि Docker Desktop नहीं चल रहा है या प्रत्युत्तर देना बंद कर दिया है तो क्या होगा?

Deepsand, Docker इंजन के बिना सैंडबॉक्स शुरू नहीं कर सकता। यदि Docker Desktop नहीं चल रहा है, तो इसे शुरू करें और इंजन के शुरू होने तक प्रतीक्षा करें। जब विंडो दोबारा फोकस पर आती है तो Deepsand दोबारा जांच करता है और स्टेटस स्ट्रिप पुनः प्रयास की पेशकश करता है।

कभी-कभी Docker Desktop अभी भी चल रहा है लेकिन इसके इंजन ने प्रतिक्रिया देना बंद कर दिया है। Deepsand को पुनः आरंभ करने से यह ठीक नहीं होता है; Docker Desktop को स्वयं पुनः आरंभ करने की आवश्यकता है।

- **इसके प्रकट होने पर इन-ऐप नियंत्रण का उपयोग करें.** यदि Deepsand Docker Desktop का पता लगाता है, तो यह स्थिति पट्टी या टर्मिनल चेतावनी में **Docker Desktop पुनः प्रारंभ करें...** दिखाता है। वह नियंत्रण Docker इंजन को पुनरारंभ करता है, जिसमें Windows पर उपयोग की जाने वाली WSL प्रक्रिया भी शामिल है, और तब तक प्रतीक्षा करता है जब तक कि कंटेनर फिर से शुरू न हो जाए।
- **Windows:** अधिसूचना क्षेत्र में Docker व्हेल पर राइट-क्लिक करें और **पुनः आरंभ करें** चुनें। यदि वह विकल्प गायब है, तो Docker Desktop खोलें, **समस्याओं का निवारण** चुनें, फिर **Docker Desktop को पुनरारंभ करें** चुनें।
- **macOS:** मेनू बार में Docker व्हेल पर क्लिक करें और **पुनः आरंभ करें** चुनें।
- **Linux:** Docker Desktop मेनू खोलें, **समस्याओं का निवारण** चुनें, फिर **Docker Desktop को पुनरारंभ करें** चुनें। यदि आप Docker Desktop के बजाय Docker Engine का उपयोग करते हैं, तो इसकी सेवा पुनः आरंभ करें, उदाहरण के लिए `sudo systemctl restart docker`।

Docker Desktop को पुनः आरंभ करने से मशीन पर प्रत्येक कंटेनर समाप्त हो जाता है, जिसमें Deepsand से असंबंधित कंटेनर भी शामिल हैं। Deepsand पुनरारंभ की पेशकश करता है लेकिन यह स्वचालित रूप से नहीं करता है। प्लेटफ़ॉर्म-विशिष्ट मेनू के लिए [Docker का समस्या निवारण दस्तावेज़](https://docs.docker.com/desktop/troubleshoot-and-support/troubleshoot/) देखें।

## क्या मैं इंटरनेट एक्सेस के बिना Deepsand का उपयोग कर सकता हूँ?

मॉडल को इसके समापन बिंदु की आवश्यकता है। `none` नेटवर्क मोड के साथ, केवल वह समापन बिंदु Deepsand प्रॉक्सी के माध्यम से पहुंच योग्य है। पैकेज इंस्टालेशन और अन्य नेटवर्क एक्सेस तब तक विफल रहेंगे जब तक आप उन होस्ट्स को अनुमति नहीं देते जिनकी उन्हें आवश्यकता है।

## मैं Deepsand को कैसे अपडेट करूं?

**सेटिंग्स** खोलें, फिर **अपडेट** खोलें और नए संस्करण की जाँच करें। रिलीज़ डाउनलोड हस्ताक्षरित अपडेट बनाता है और एक इंस्टॉल करने के बाद ऐप को पुनरारंभ करता है। अद्यतन स्थापित करने से सैंडबॉक्स चलना बंद हो जाता है।

## क्या कोई कमांड-लाइन इंटरफ़ेस है?

हाँ। `deepsandctl` `doctor`, `plan`, `run`, `watch`, `requests` और `network` जैसे हेडलेस कमांड प्रदान करता है। डेस्कटॉप ऐप और CLI `deepsand-core` में समान पॉलिसी कोड साझा करते हैं।

## मैं किसी सुरक्षा समस्या की रिपोर्ट कैसे करूँ?

किसी सुरक्षा समस्या के लिए सार्वजनिक निर्गम न खोलें। रिपॉजिटरी के सुरक्षा रिपोर्टिंग चैनल के माध्यम से अनुरक्षकों से निजी तौर पर संपर्क करें और समस्या को पुन: उत्पन्न करने के लिए पर्याप्त विवरण शामिल करें।
