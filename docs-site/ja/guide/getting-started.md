# はじめる

Deepsand を使用すると、AI コーディング アシスタントにコンピュータの他の部分へのアクセスを許可せずに、実際のプロジェクトで AI コーディング アシスタントと作業することができます。基本的なフローを使用するために、Docker やコマンド ラインを理解する必要はありません。

まず全体像を知りたい場合は、[Deepsandとは何ですか?](./what-is-deepsand) をお読みください。

## 要件

- Windows または macOS の Docker Desktop、または Linux の Docker Engine。
- Windows、macOS、または Linux コンピューター。 [ダウンロードページ](../download) はシステムを検出し、一致するインストーラーをリストします。
- ソースから Deepsand をビルドしない限り、Node.js または Rust のインストールは必要ありません。

Deepsand がサンドボックスを開始するには、Docker Desktop が実行されている必要があります。デーモンがまだ起動中の場合は、ステータス ストリップにその旨が表示され、再度確認するよう求められます。 Docker Desktop は実行されていても応答しない場合もあります。 Deepsand がデーモンが応答していないと言う場合は、Docker Desktop を再起動します。 Deepsand が Docker Desktop を検出すると、**Docker Desktop を再起動します…** コントロールが表示されます。 [Docker Desktop が実行されていない、または応答を停止した場合の対処方法](./faq#what-if-docker-desktop-is-not-running-or-has-stopped-responding)を参照してください。

## インストール

[Deepsand ダウンロードページ](../download) を開きます。オペレーティング システムを検出し、現在の GitHub リリースの最新の Windows、macOS、および Linux インストーラーを一覧表示します。コンピュータ用のパッケージを選択してインストールし、Deepsand を起動します。

Deepsand 自体を開発している場合は、リポジトリの README にsource-build コマンドと hot-reload コマンドが含まれています。

## 最初の実行

Deepsand を使用する前に、DeepCode をインストールまたは構成する必要はありません。 Deepsand はサンドボックス内で DeepCode を実行し、モデルとエンドポイントに適切なデフォルトが付属しています。

必要なのは、モデル API キーです。次のセクションでは、DeepSeek キーを取得する方法について説明します。または、別のプロバイダーからキーを使用することもできます。 **設定→APIキー**に保存します。

このコンピューターですでに DeepCode CLI を使用している場合、Deepsand は代わりに、既存の DeepCode 構成からモデル、ベース URL、およびキーを継承できます。プロジェクトは、独自の設定でこれらの資格情報をオーバーライドすることもできます。

## API キーを取得する

Deepsand では、アシスタントを実行する前に、モデル プロバイダーからの API キーが必要です。

- [DeepSeek API キーを取得する](./deepseek-api)の後に**お持ちでない場合:**が続きます。アカウントの作成、クレジットの追加、キーの作成、そして Deepsand に戻るまでの手順を説明します。
- **すでにお持ちの場合:** **設定** を開き、**APIキー** フィールドに貼り付けて、**キーを保存** を選択します。
- **プロジェクト固有のキーが必要な場合:** は、そのプロジェクトの設定を開いて、代わりにそこに入力します。

アプリ全体のキーは、Deepsand の状態ファイルではなく、オペレーティング システムのキーストアに保存されます。保存後、ウィンドウには最後の 4 文字のみが表示されます。

## プロジェクトを作成する

1. サイドバーで **新しいプロジェクト** を選択します。
2. プロジェクトに名前を付けます。
3. 作業ディレクトリを選択します。
4. プロジェクトを作成します。

作業ディレクトリはサンドボックス内の `/workspace` になります。 Deepsand は、ファイルシステムのルート、ホーム ディレクトリ、資格情報ストア、独自のデータ ディレクトリなどのパスを拒否します。

## モデルを選択してください

ほとんどのタスクには **フラッシュモデル** を使用します。 Deepsand のデフォルトは `deepseek-v4-flash` で、日常のコーディング、説明、編集にはこれが安価な選択肢です。フラッシュが明らかにタスクに苦戦している場合にのみ、`deepseek-v4-pro` に切り替えてください。プロモデルはランニングコストが高くなります。

モデルは、プロジェクト ヘッダーから **設定** で変更するか、DeepCode ターミナルの `/model` を使用して変更できます。

## 思考レベルを選択してください

思考スライダーは、プロジェクト ヘッダーのモデル セレクターの隣にあります。モデルが答える前にどれだけ推論を行うかを制御します。

- **オフ：**何も考えていない。最速ですが、最も慎重ではありません。
- **素早い：** ちょっと考えて、細かく指定された編集を行います。
- **バランスの取れた:** 適度な思考と中止まり。これは実際の作業では賢明なデフォルトです。
- **深い：** 最大の推論。最も遅く、最も高価です。
- **デフォルト：** はホスト `settings.json` に従います。何も表示されない場合、DeepCode はバランス状態に戻ります。

ほとんどのタスクでは、スライダーを **バランスの取れた** に維持します。すべてのリクエストに対して、最も遅く、最もコストのかかる推論に料金を支払うことなく、良好な結果が得られます。 **深い** は本当に難しい問題にのみ使用し、**オフ** または **素早い** は小規模で予測可能な編集に使用します。

## プロジェクトを実行する

1. プロジェクトを選択します。
2. **走る**を押します。
3. イメージが見つからない場合、Deepsand は最初にイメージをビルドし、[アクティビティ] タブにビルド出力を表示します。
4. DeepCode CLI はコンテナ内で開始され、ターミナルに表示されます。

サンドボックスを停止するとコンテナも終了します。再度開始すると、以前の DeepCode セッションが存在する場合、そのセッションが再開されます。

## DeepCode 端末の使用

**ターミナル** タブはライブ DeepCode CLI セッションです。リクエストを入力して **入力** を押すか、スラッシュ コマンドを使用してセッションを制御します。 `/new` は新しい会話を開始し、`/resume` は以前の会話を継続し、`/model` はモデルを変更し、`/` はコマンド メニューを開きます。

主なコマンド、キーボード ショートカット、および回復手順については、[DeepCode 端末の使用](./deepcode-terminal) をお読みください。

## 許可リクエストに応答する

DeepCode がディレクトリ、ネットワーク宛先、ツール、または別のリソースを必要とする場合、Deepsand はサンドボックスを一時停止し、リクエストを表示します。

- **アクセスを許可する** はリクエストを許可し、セッションを再開します。
- **拒否** はそれを拒否し、決定が最終的なものであることをモデルに伝えます。
- ディレクトリ許可により、新しいマウントが接続されたコンテナが再作成されます。

機密ファイルを含むディレクトリへのアクセスを許可する前に、[サンドボックスの仕組み](./security) を読んでください。

## どこで物を見つけるか

|エリア |それが示すもの |
| --- | --- |
|ターミナル |サンドボックス内のライブ DeepCode セッション。 |
|権限 |共有ディレクトリ、ネットワーク許可リスト、監査証跡。 |
|ツール |プロジェクト イメージに焼き付けられたツール。選択を変更すると、イメージが再構築されます。 |
|秘密 |開始時に環境変数として挿入される暗号化された値。 |
|アクティビティ |正確な `docker run` 引数、ビルド ログ、ブロックされた出力試行。 |
