# ボンネットの下で

このページは、システムの技術的な形状を知りたい開発者向けです。わかりやすい説明を探している場合は、[Deepsandとは何ですか?](./what-is-deepsand) から始めてください。

## 建築

Deepsand は、次の 3 つの主要なレイヤーを持つ Tauri デスクトップ アプリです。

- **窓** は SolidJS インターフェイスです。状態をレンダリングし、インテントを送信します。政策を決めるものではありません。
- **おうし座層** はデスクトップ コマンドを公開し、同じコマンド サーフェスをリモート クライアント用のループバック HTTP サーバーに変換します。
- **`deepsand-core`** がルールを所有します。パス検証、`docker run` プラン、パーミッション ブローカー、出力プロキシ、暗号化されたシークレット ストア、および状態ストアはすべてそこに存在します。

デスクトップ アプリとコマンド ライン ドライバー `deepsandctl` は同じコアを使用するため、セキュリティ上の決定において両者が乖離することはありません。

## 1 つのプロジェクト、1 つのコンテナ

各プロジェクトは、独自の Docker コンテナーと独自の状態ボリュームを取得します。プロジェクト ディレクトリは `/workspace` にマウントされます。他のホスト ディレクトリには明示的な許可が必要です。

`policy::plan_run` は、完全な `docker run` argv を 1 か所に構築します。 [アクティビティ] タブには、マウント、機能、ネットワーク モード、読み取り専用パスなどの正確な計画が表示されます。

コンテナは意図的に制約されています。

- ルート ファイルシステムは読み取り専用で、`/tmp` および `/run` のサイズに合わせた tmpfs マウントが使用されます。
- 応答スプールと状態ディレクトリは読み取り専用でマウントされます。
- コンテナー ランタイム ソケットは名前によって拒否されます。
- DeepCode が実行される前に機能が削除され、`no-new-privileges` が設定されます。
- コンテナー ランタイム ソケットおよびその他の禁止されたマウントは、より弱いプランを生成するのではなく、フェール クローズされます。

## 権限

サンドボックスは追加のアクセスを要求できますが、それを許可することはできません。許可リクエストはスプールに書き込まれます。ホスト ブローカーはそれを検証し、コンテナを一時停止します。オペレーターはリクエストを見て判断します。

ディレクトリ要求を承認すると、新しいバインド マウントでコンテナが再作成され、セッションが再開されます。拒否は 2 つの答えのうちの 1 つであり、モデルにはどちらが最終であるかが通知されます。**二度と聞かないでください** が最終的ですが、**今じゃない** は今回は拒否し、モデルは後でもう一度尋ねる可能性があると言います。最終的な拒否はプロジェクトに保存され、ホストによって強制されます。パスまたはその下にあるものに対してマウントは作成されず、拒否されたホストはそのサブドメインを対象とする拒否ルールになります。ブロックは権限にリストされており、そこで解除することができます。後戻りできない決定は選択ではなく罠であるためです。

サンドボックスにすでにあるものに対するリクエストは、説明付きで拒否されます。サイレント承認はオペレーターが決して与えなかった同意となるため、自動承認パスはありません。

## ネットワーキング

ネットワーク ポリシーには 4 つのモードがあります。

|モード |行動 |
| --- | --- |
| `none` | Deepsand 出力プロキシを経由するモデル エンドポイントのみ。 |
| `allowlisted` |モデルのエンドポイント、プロキシ、名前付きホスト、アドレス、ポート。 |
| `internet` |コンテナ内でブロックされたローカル範囲とプライベート範囲によるインターネット アクセス。 |
| `full` |ローカルネットワークブロックのないインターネットアクセス。 |

ホスト名エントリはプロキシによって解決され、プライベート、ループバック、リンクローカル、予約された結果は拒否されます。アドレス エントリはコンテナによって直接強制され、これによりデータベース クライアントや他の非 HTTP プログラムが接続できるようになります。名前付きポートはホスト ループバックでのみ公開されます。

## 秘密と最新情報

シークレットは、オペレーティング システムのキーストアが保持するキーを使用して保存時に暗号化されます。これらは、コマンドライン値としてではなく、環境ファイルを通じてコン​​テナーに渡され、サンドボックスの開始時にのみ挿入されます。

リリース ビルドでは、署名された更新をインストールする前に検証します。署名キーがリポジトリに保存されることはありません。

## コマンドライン

`deepsandctl` はヘッドレス サーフェスを提供します。

```bash
deepsandctl doctor
deepsandctl plan <project> --offline
deepsandctl run <project>
deepsandctl watch <project>
deepsandctl requests <project>
deepsandctl network <project> <mode>
```

`plan --offline` は、コンテナーを起動せずに正確な `docker run` argv を出力します。これは、変更されたポリシーを確認するのに役立ちます。
