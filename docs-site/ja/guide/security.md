# サンドボックスの仕組み

簡単に言うと、アシスタントは、ユーザーが選択したプロジェクトとユーザーが承認したフォルダー内で作業でき、コンピューター上の他の場所では作業できません。

Deepsand の約束は限定的でテスト可能です。サンドボックスはプロジェクト ディレクトリと明示的に許可したディレクトリに到達できますが、それ以外には到達できません。

## 境界線

コンテナーには、Deepsand が選択したバインド マウント以外のホスト ファイルシステムのビューがありません。コンテナのマウント名前空間内には他のホスト パスが存在しないため、エスケープ先のホスト ファイルがありません。

ここで説明するその他のすべては、その境界の上での多層防御です。

## 強制される内容

- ワークスペースと明示的な許可のみがホストからマウントされます。
- 応答スプールと状態ディレクトリは読み取り専用でマウントされます。
- コンテナー ランタイム ソケットは名前によって拒否されます。
- コンテナーのルート ファイルシステムは読み取り専用で、`/tmp` および `/run` のサイズの一時ファイルシステムを備えています。
- シンボリック リンクはパスがチェックされる前に解決されるため、リンクによって禁止されたターゲットを偽装することはできません。
- 特権は DeepCode が実行される前に削除され、`no-new-privileges` によって特権が回復されなくなります。

## ネットワークモード

|モード |何ができるのか |
| --- | --- |
|なし | Deepsand プロキシを介したモデル エンドポイントのみ。 |
|許可リストに登録済み |モデルのエンドポイント、プロキシ、およびホワイトリスト上のホストまたはアドレス。 |
|インターネット |コンテナ内でブロックされたローカル範囲とプライベート範囲によるインターネット アクセス。 |
|フル |ローカルネットワークブロックのないインターネットアクセス。サンドボックスが本当にローカル ネットワークを必要とする場合にのみ使用してください。 |

ホワイトリストに登録されたホスト名はプロキシを通過します。プロキシは名前自体を解決し、プライベート アドレス空間での結果を拒否します。データベース クライアントや他の非 HTTP プログラムはプロキシを使用できないため、ホワイトリストに登録されたアドレスはコンテナのルールによって直接許可されます。エントリで指定されたポートは、すべてのインターフェイスではなく、ホストのループバックでも公開されます。

## あなたが決めること

Deepsand が自動的にアクセスを許可することはありません。リクエストは、要求しているパス、ホスト、ツール、またはリソースとともに届きます。サンドボックスは、ユーザーが決定するまで一時停止したままになります。

サンドボックスがすでに持っているものに対するリクエストは、説明付きで拒否されます。これは、自動許可は決して与えていない同意であるためです。曖昧なものは何でもあなたに届きます。

## 保護できないもの

- モデルプロバイダーは、送信されたコンテンツを確認できます。
- ワークスペースに配置したファイルはサンドボックスに表示され、変更または削除される可能性があります。
- 不正な形式のツールまたはモデル命令がアクセスを要求する可能性があります。決定はあなた次第です。
- Docker 自体が境界の外にあります。 Docker Desktop とホスト オペレーティング システムを最新の状態に保ちます。
