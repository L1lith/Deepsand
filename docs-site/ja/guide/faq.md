# よくある質問

## DeepCode は私のホーム ディレクトリを認識しますか?

いいえ。サンドボックスは、`/workspace` にあるプロジェクト ディレクトリと、明示的に付与したディレクトリを認識します。ホスト ファイルシステムの残りの部分はマウントされていません。

## ディレクトリ要求を承認するとどうなりますか?

Deepsand はディレクトリを許可として追加し、新しいマウントが接続されたコンテナを再作成し、DeepCode セッションを再開します。実行中のサンドボックスは、再作成されなければバインド マウントを取得できません。

## 私の会話はどこに保存されますか?

会話履歴、セッション、添付ファイル、生成されたスキルは、プロジェクトごとの Docker ボリュームに保存されます。ディスク上のプロジェクト フォルダーには、コードとファイルのみが含まれます。

Deepsand からプロジェクトを削除しても、そのボリュームは削除されません。プロジェクトの DeepCode データを消去すると、ボリュームは削除されますが、プロジェクト フォルダーはそのまま残ります。

## API キーとシークレットはどこに保存されますか?

シークレットは、オペレーティング システムのキーストアが保持するキーを使用して保存時に暗号化され、サンドボックスの起動時にのみ環境変数としてサンドボックスに挿入されます。インターフェイスには名前と長さが表示されますが、保存されている値は表示されません。

資格情報はホストの DeepCode 構成から継承することもできます。プロジェクトフォルダーにはコピーされません。

## 各プロジェクトで異なるモデルを使用できますか?

はい。プロジェクトは、ホスト構成を継承したり、独自の設定でモデル、ベース URL、資格情報をオーバーライドしたりできます。ヘッダー セレクターはプロジェクトのモデルを選択することもできます。 **構成に従う** は、プロジェクトがピン留めしていないことを意味します。

## コストを抑えるにはどのモデルを使用すればよいですか?

ほとんどのタスクにはフラッシュ モデルを使用します。 Deepsand のデフォルトは `deepseek-v4-flash` で、日常のコーディング、説明、編集にはこれが安価な選択肢です。 `deepseek-v4-pro` は、フラッシュに明らかに問題がある場合や、プロ モデルの方が実行コストがかかるため、追加の機能が必要な作業用に予約してください。

プロジェクトヘッダーまたは DeepCode ターミナルの `/model` からモデルを切り替えます。 Deepsand を初めて試す場合は、フラッシュから始めて、それが必要なタスクがある場合にのみプロに移行してください。

## 思考スライダーは何をするのですか?

思考スライダーは、プロジェクト ヘッダーのモデル セレクターの隣にあります。モデルが応答する前にどれだけの推論を行うかを制御します。

|停止 |意味 |
| --- | --- |
| **オフ** |答える前に考えないでください。最速ですが、最も慎重ではありません。 |
| **素早い** |細かく指定された編集については、少し考えてみましょう。 |
| **バランスの取れた** |適度な思考。中間停止であり、実際の作業では賢明なデフォルトです。 |
| **深い** |モデルができる限り真剣に考えてください。最も遅く、最も高価です。 |
| **デフォルト** |ホスト `settings.json` に従います。何も表示されない場合、DeepCode はバランス状態に戻ります。 |

ほとんどのタスクでは、スライダーを **バランスの取れた** に維持します。これは中間の設定であり、すべてのリクエストで最も遅く、最も高価な推論に料金を支払うことなく、良好な結果が得られます。本当に難しい問題の場合のみ **深い** に移行し、小規模で予測可能な編集には **オフ** または **素早い** を使用してください。

## Deepsand は DeepSeek でのみ動作しますか?

いいえ。DeepSeek は Deepsand に付属するモデルおよびエンドポイントであるためデフォルトですが、Deepsand はモデル名、ベース URL、および API キーを使用して DeepCode CLI を構成します。 CLI が呼び出すことができる API を公開する別のプロバイダー (通常は OpenAI 互換エンドポイント) を指すことができます。

プロバイダーのベース URL とモデルを **設定** またはプロジェクト独自の資格情報に設定し、そのプロバイダーの API キーを同じ場所に保存します。サンドボックスのネットワーク ポリシーでは、プロバイダーのエンドポイントも許可する必要があります。

## Docker Desktop が実行されていない場合、または応答を停止した場合はどうなりますか?

Deepsand は、Docker エンジンなしではサンドボックスを開始できません。 Docker Desktop が動作していない場合は、Docker Desktop を始動し、エンジンの始動が完了するまで待ちます。 Deepsand は、ウィンドウがフォーカスを取り戻したときに再チェックし、ステータス ストリップが再試行を提案します。

Docker Desktop はまだ実行中ですが、エンジンが応答を停止している場合があります。 Deepsand を再起動しても問題は解決しません。 Docker Desktop自体を再起動する必要があります。

- **アプリ内コントロールが表示されたらそれを使用します。** Deepsand が Docker Desktop を検出すると、ステータス ストリップまたは端末警告に **Docker Desktop を再起動します…** が表示されます。このコントロールは、Windows で使用する WSL プロセスを含む Docker エンジンを再起動し、コンテナーが再び起動できるようになるまで待機します。
- **Windows:** 通知領域の Docker クジラを右クリックし、[**再起動**] を選択します。そのオプションがない場合は、Docker Desktop を開き、**トラブルシューティング**、**Docker Desktopを再起動します** の順に選択します。
- **macOS:** メニュー バーの Docker クジラをクリックし、**再起動** を選択します。
- **Linux:** Docker Desktop メニューを開き、**トラブルシューティング**、**Docker Desktopを再起動します** の順に選択します。 Docker Desktop の代わりに Docker Engine を使用する場合は、そのサービス (`sudo systemctl restart docker` など) を再起動します。

Docker Desktop を再起動すると、Deepsand に関係のないコンテナを含む、マシン上のすべてのコンテナが終了します。 Deepsand は再起動を提案しますが、自動的には実行されません。プラットフォーム固有のメニューについては、[Docker のトラブルシューティング ドキュメント](https://docs.docker.com/desktop/troubleshoot-and-support/troubleshoot/) を参照してください。

## インターネットにアクセスせずに Deepsand を使用できますか?

モデルにはエンドポイントが必要です。 `none` ネットワーク モードでは、そのエンドポイントのみが Deepsand プロキシ経由で到達可能です。必要なホストを許可しない限り、パッケージのインストールやその他のネットワーク アクセスは失敗します。

## Deepsand を更新するにはどうすればよいですか?

**設定**、**アップデート** の順に開き、新しいバージョンがあるかどうかを確認します。リリース ビルドでは、署名された更新をダウンロードし、インストール後にアプリを再起動します。アップデートをインストールすると、サンドボックスの実行が停止します。

## コマンドラインインターフェイスはありますか?

はい。 `deepsandctl` は、`doctor`、`plan`、`run`、`watch`、`requests`、`network` などのヘッドレス コマンドを提供します。デスクトップ アプリと CLI は、`deepsand-core` の同じポリシー コードを共有します。

## セキュリティ問題を報告するにはどうすればよいですか?

セキュリティ上の問題については公開問題を開かないでください。リポジトリのセキュリティ報告チャネルを通じてメンテナに非公開で連絡し、問題を再現するのに十分な詳細を含めてください。
