# تحت غطاء محرك السيارة

هذه الصفحة مخصصة للمطورين الذين يريدون الشكل الفني للنظام. إذا كنت تبحث عن شرح بلغة واضحة، فابدأ بـ [ما هو Deepsand؟](./what-is-deepsand).

## بنيان

Deepsand هو تطبيق Tauri لسطح المكتب مع ثلاث طبقات رئيسية:

- **النافذة** هي واجهة SolidJS. فإنه يجعل الحالة ويرسل النوايا؛ فهو لا يقرر السياسة.
- يعرض **طبقة التوري** أوامر سطح المكتب ويترجم نفس سطح الأوامر إلى خادم HTTP استرجاعي للعملاء البعيدين.
- **`deepsand-core`** تمتلك القواعد. التحقق من صحة المسار، وخطة `docker run`، ووسيط الأذونات، ووكيل الخروج، والمخزن السري المشفر، والمخزن الحكومي كلها موجودة هناك.

يستخدم تطبيق سطح المكتب وبرنامج تشغيل سطر الأوامر `deepsandctl` نفس النواة، لذلك لا يمكن أن ينفصلا عن قرار أمني.

## مشروع واحد، حاوية واحدة

يحصل كل مشروع على حاوية Docker الخاصة به وحجم الحالة الخاص به. تم تثبيت دليل المشروع على `/workspace`؛ تتطلب أدلة المضيف الأخرى منحًا صريحة.

يقوم `policy::plan_run` ببناء `docker run` argv الكامل في مكان واحد. تعرض علامة التبويب "النشاط" تلك الخطة الدقيقة، بما في ذلك عمليات التثبيت والإمكانيات ووضع الشبكة ومسارات القراءة فقط.

الحاوية مقيدة عمدا:

- نظام الملفات الجذر للقراءة فقط، مع حجم tmpfs المتصاعد لـ `/tmp` و`/run`.
- يتم تثبيت التخزين المؤقت للاستجابة ودليل الحالة للقراءة فقط.
- يتم رفض مآخذ توصيل وقت تشغيل الحاوية بالاسم.
- يتم إسقاط القدرات قبل تشغيل DeepCode، ويتم تعيين `no-new-privileges`.
- تفشل مآخذ توصيل وقت تشغيل الحاوية والتركيبات المحظورة الأخرى في الإغلاق بدلاً من إنتاج خطة أضعف.

## الأذونات

يمكن لصندوق الحماية أن يطلب المزيد من الوصول، لكنه لا يستطيع منحه. تتم كتابة طلب إذن إلى التخزين المؤقت؛ يقوم الوسيط المضيف بالتحقق من صحة ذلك وإيقاف الحاوية مؤقتًا. يرى المشغل الطلب ويقرر.

تؤدي الموافقة على طلب الدليل إلى إعادة إنشاء الحاوية باستخدام رابط الربط الجديد واستئناف الجلسة. يعتبر الرفض نهائيًا ويتم إبلاغ النموذج به.

يتم رفض طلب الحصول على شيء موجود بالفعل في وضع الحماية مع توضيح ذلك. لا يوجد مسار موافقة تلقائية، لأن الموافقة الصامتة ستكون بمثابة موافقة لم يقدمها المشغل مطلقًا.

## الشبكات

تشتمل سياسة الشبكة على أربعة أوضاع:

| الوضع | السلوك |
| --- | --- |
| `none` | نقطة نهاية النموذج فقط من خلال وكيل الخروج Deepsand. |
| `allowlisted` | نقطة نهاية النموذج والوكيل والمضيفين والعناوين والمنافذ المسماة. |
| `internet` | الوصول إلى الإنترنت، مع حظر النطاقات المحلية والخاصة داخل الحاوية. |
| `full` | الوصول إلى الإنترنت دون كتلة الشبكة المحلية. |

يتم حل إدخال اسم المضيف بواسطة الوكيل، الذي يرفض النتائج الخاصة والاسترجاعية والارتباط المحلي والمحفوظة. يتم فرض إدخال العنوان مباشرة بواسطة الحاوية، وهو ما يسمح لعميل قاعدة البيانات أو أي برنامج آخر غير HTTP بالاتصال. يتم نشر منفذ مسمى على استرجاع المضيف فقط.

## أسرار وتحديثات

يتم تشفير الأسرار أثناء الراحة باستخدام مفتاح يحتفظ به مخزن مفاتيح نظام التشغيل. يتم تمريرها إلى الحاوية من خلال ملف بيئة، وليس كقيمة سطر أوامر أبدًا، ويتم إدخالها فقط عند بدء وضع الحماية.

تتحقق إصدارات الإصدار من التحديثات الموقعة قبل تثبيتها. لا يتم تخزين مفتاح التوقيع في المستودع أبدًا.

## سطر الأوامر

يوفر `deepsandctl` السطح مقطوع الرأس:

```bash
deepsandctl doctor
deepsandctl plan <project> --offline
deepsandctl run <project>
deepsandctl watch <project>
deepsandctl requests <project>
deepsandctl network <project> <mode>
```

يقوم `plan --offline` بطباعة argv `docker run` بالضبط دون بدء حاوية، وهو أمر مفيد لمراجعة السياسة التي تم تغييرها.
