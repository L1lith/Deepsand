# ابدء

يساعدك Deepsand على العمل مع مساعد ترميز الذكاء الاصطناعي في مشروع حقيقي دون منح هذا المساعد إمكانية الوصول إلى بقية جهاز الكمبيوتر الخاص بك. لا تحتاج إلى فهم Docker أو سطر الأوامر لاستخدام التدفق الأساسي.

إذا كنت تريد الصورة الأكبر أولاً، فاقرأ [ما هو Deepsand؟](./what-is-deepsand).

## متطلبات

- Docker Desktop على Windows أو macOS أو Docker Engine على Linux.
- كمبيوتر Windows أو macOS أو Linux. يكتشف [صفحة التنزيلات](../download) النظام ويسرد المثبتات المطابقة.
- ليست هناك حاجة إلى تثبيت Node.js أو Rust إلا ​​إذا كنت تقوم ببناء Deepsand من المصدر.

يجب تشغيل Docker Desktop قبل أن يتمكن Deepsand من بدء وضع الحماية. إذا كان البرنامج الخفي لا يزال قيد التشغيل، فسيشير شريط الحالة إلى ذلك ويعرض عليك التحقق مرة أخرى. يمكن أيضًا أن يكون Docker Desktop قيد التشغيل ولكنه لا يستجيب؛ إذا قال Deepsand أن البرنامج الخفي لا يجيب، فأعد تشغيل Docker Desktop. عندما يكتشف Deepsand Docker Desktop فإنه يظهر عنصر تحكم **إعادة تشغيل Docker Desktop...**. انظر [ماذا تفعل إذا لم يكن Docker Desktop قيد التشغيل أو توقف عن الاستجابة](./faq#what-if-docker-desktop-is-not-running-or-has-stopped-responding).

## ثَبَّتَ

افتح [صفحة التنزيلات Deepsand](../download). فهو يكتشف نظام التشغيل الخاص بك ويسرد أحدث مثبتات Windows وmacOS وLinux من الإصدار الحالي GitHub. اختر الحزمة لجهاز الكمبيوتر الخاص بك، وقم بتثبيتها، ثم قم بتشغيل Deepsand.

إذا كنت تقوم بتطوير Deepsand نفسه، فإن المستودع README يحتوي على أوامر إنشاء المصدر وإعادة التحميل السريع.

## التشغيل الأول

لا تحتاج إلى تثبيت DeepCode أو تهيئته قبل استخدام Deepsand. يقوم Deepsand بتشغيل DeepCode داخل صندوق الحماية ويأتي مع إعدادات افتراضية معقولة للنموذج ونقطة النهاية.

الشيء الوحيد الذي تحتاجه هو مفتاح API النموذجي. يشرح القسم التالي كيفية الحصول على مفتاح DeepSeek، أو يمكنك استخدام مفتاح من مزود آخر. احفظه في **الإعدادات → مفتاح API**.

إذا كنت تستخدم DeepCode CLI بالفعل على هذا الكمبيوتر، فيمكن لـ Deepsand بدلاً من ذلك أن ترث النموذج وعنوان URL الأساسي والمفتاح من تكوين DeepCode الموجود لديك. يمكن للمشروع أيضًا تجاوز بيانات الاعتماد هذه في إعداداته الخاصة.

## احصل على مفتاح API

يحتاج Deepsand إلى مفتاح API من موفر الطراز قبل أن يتمكن المساعد من التشغيل.

- **إذا لم يكن لديك واحدة:** اتبع [احصل على مفتاح DeepSeek API](./deepseek-api). فهو يمر عبر إنشاء حساب وإضافة رصيد وإنشاء مفتاح والعودة إلى Deepsand.
- **إذا كان لديك واحدة بالفعل:** افتح **إعدادات**، والصقه في الحقل **مفتاح API** وحدد **حفظ المفتاح**.
- **إذا كنت تريد مفتاحًا خاصًا بالمشروع:** افتح إعدادات هذا المشروع وأدخله هناك بدلاً من ذلك.

يتم الاحتفاظ بالمفتاح على مستوى التطبيق في مخزن المفاتيح الخاص بنظام التشغيل لديك، وليس في ملف حالة Deepsand. تعرض النافذة الأحرف الأربعة الأخيرة فقط بعد الحفظ.

## إنشاء مشروع

1. حدد **مشروع جديد** في الشريط الجانبي.
2. إعطاء المشروع اسما.
3. اختر دليل العمل.
4. إنشاء المشروع.

يصبح دليل العمل `/workspace` داخل صندوق الحماية. يرفض Deepsand مسارات مثل جذر نظام الملفات والدليل الرئيسي ومخازن بيانات الاعتماد ودليل البيانات الخاص به.

## اختر نموذجًا

استخدم **نموذج فلاش** لمعظم المهام. يتم تعيين Deepsand افتراضيًا على `deepseek-v4-flash`، وهو الخيار الأرخص للبرمجة والشروحات والتحريرات اليومية. قم بالتبديل إلى `deepseek-v4-pro` فقط عندما يواجه الفلاش صعوبة في إنجاز مهمة ما؛ النموذج الاحترافي يكلف تشغيله أكثر.

يمكنك تغيير النموذج في **إعدادات**، من رأس المشروع، أو باستخدام `/model` في محطة DeepCode.

## اختر مستوى التفكير

يوجد شريط تمرير التفكير بجوار محدد النموذج في رأس المشروع. إنه يتحكم في مقدار التفكير الذي يقوم به النموذج قبل الإجابة.

- **عن:** لا يوجد تفكير. الأسرع، ولكن الأقل حذرا.
- **سريع:** قليل من التفكير لإجراء تعديلات صغيرة محددة جيدًا.
- **متوازن:** التفكير المعتدل والتوقف الأوسط. هذا هو الوضع الافتراضي المعقول للعمل الحقيقي.
- **عميق:** الحد الأقصى للاستدلال. الأبطأ والأغلى.
- **تقصير:** يؤجل إلى المضيف `settings.json`؛ إذا لم يذكر شيئًا، فسيعود DeepCode إلى "متوازن".

احتفظ بشريط التمرير على **متوازن** لمعظم المهام. إنه يعطي نتائج جيدة دون الدفع مقابل التفكير الأبطأ والأكثر تكلفة في كل طلب. استخدم **عميق** فقط للمشكلات الصعبة حقًا، و**عن** أو **سريع** للتعديلات الصغيرة التي يمكن التنبؤ بها.

## تشغيل المشروع

1. حدد المشروع.
2. اضغط على **يجري**.
3. إذا كانت الصورة مفقودة، يقوم Deepsand بإنشائها أولاً ويعرض مخرجات البناء في علامة تبويب النشاط.
4. يبدأ DeepCode CLI داخل الحاوية ويظهر في الجهاز.

يؤدي إيقاف وضع الحماية إلى إنهاء الحاوية. يؤدي بدء تشغيله مرة أخرى إلى استئناف جلسة DeepCode السابقة عند وجودها.

## باستخدام محطة DeepCode

علامة التبويب **صالة** هي جلسة DeepCode CLI المباشرة. اكتب طلبًا واضغط على **يدخل**، أو استخدم أمر الشرطة المائلة للتحكم في الجلسة. يبدأ `/new` محادثة جديدة، ويواصل `/resume` محادثة سابقة، ويغير `/model` النموذج، ويفتح `/` قائمة الأوامر.

اقرأ [باستخدام محطة DeepCode](./deepcode-terminal) للتعرف على الأوامر الرئيسية واختصارات لوحة المفاتيح وخطوات الاسترداد.

## الرد على طلبات الإذن

عندما يحتاج DeepCode إلى دليل أو وجهة شبكة أو أداة أو مورد آخر، يقوم Deepsand بإيقاف صندوق الحماية مؤقتًا ويظهر الطلب.

- يسمح **منح الوصول** بالطلب ويستأنف الجلسة.
- **ليس الآن** يرفض ذلك هذه المرة؛ قد يسأل النموذج مرة أخرى لاحقًا.
- يرفضه **لا تسأل مرة أخرى**، ثم يرفض Deepsand هذا المسار (وكل شيء تحته) أو ذلك المضيف (ونطاقاته الفرعية) نفسه، وليس فقط بالكلمات. يتم إدراج كل كتلة في الأذونات، حيث يمكنك رفعها مرة أخرى.
- تقوم منحة الدليل بإعادة إنشاء الحاوية مع التحميل الجديد المرفق.

اقرأ [كيف يعمل صندوق الرمل](./security) قبل منح الوصول إلى الدليل الذي يحتوي على ملفات حساسة.

## أين تجد الأشياء

| المنطقة | ما يظهر |
| --- | --- |
| المحطة | جلسة DeepCode المباشرة داخل وضع الحماية. |
| أذونات | الدلائل المشتركة والقائمة المسموح بها للشبكة ومسار التدقيق. |
| أدوات | الأدوات المدمجة في صورة المشروع، والقدرات المجمعة، واللغات، ومديري الحزم، والمرافق، والهندسة العكسية. لا يوجد شيء قيد التشغيل بشكل افتراضي، وتغيير التحديد يؤدي إلى إعادة بناء الصورة. |
| أسرار | يتم إدخال القيم المشفرة كمتغيرات البيئة في البداية. |
| النشاط | وسيطات `docker run` الدقيقة وسجل البناء ومحاولات الخروج المحظورة. |
