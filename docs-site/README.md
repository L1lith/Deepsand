# Deepsand documentation site

The user documentation is a VitePress site under `docs-site/`. English Markdown
is the source; the other 16 locales are generated from it.

## Local development

```bash
npm install
npm run docs           # dev server with hot reload, opens the browser
npm run docs:dev       # dev server without opening a browser
npm run docs:preview   # build, then serve the production output locally
npm run docs:build     # writes docs-site/.vitepress/dist
```

`npm run docs` and `npm run docs:dev` serve at <http://localhost:5173>.
`npm run docs:preview` builds first, then serves the built site.

## Translations

The locale pages and the VitePress UI labels are generated by:

```bash
npm run docs:translate
```

That script reads the English pages, protects commands, inline code, links,
bold text and product names, translates the remaining text and the home-page
frontmatter (hero copy, actions and feature cards), and writes:

- `docs-site/<locale>/...`
- `docs-site/.vitepress/i18n.generated.json`

The main pages are **Download** for OS-detected release downloads, **What is
Deepsand?** for a plain-language introduction, **Getting started** for the guided
flow, **Get a DeepSeek API key** for the account and key setup, **Using the
DeepCode terminal** for the main commands and shortcuts, **How the sandbox works**
and **Under the hood** for technical readers, and the **FAQ** for quick answers.

All pages are translated into the 16 non-English locales. The generated files
are committed, so a normal docs build does not need network access. Re-run
`npm run docs:translate` after changing an English page. To retranslate only
the page that changed, or only one locale:

```bash
DOCS_TRANSLATE_PAGES=download.md npm run docs:translate
DOCS_TRANSLATE_LANGS=es npm run docs:translate
```

A wording change that must survive regeneration belongs in the `OVERRIDES`
map in `docs-site/scripts/translate-docs.mjs`: key it by locale and page, and
use a dot path into the frontmatter (`hero.tagline`), an exact English source
line, or a UI label. A path or line that no longer matches the English source
fails the run rather than silently disappearing. `npm run docs:check` validates
every override against the English source without calling the translator; the
docs workflow runs it before the build.

The translation output is machine-generated; a native-speaker review is
worthwhile before publishing major wording changes. The generator protects
Vue component tags and `<script>` blocks, because translating those breaks the
page rather than translating it.

Supported locales: English, Simplified Chinese, Hindi, Spanish, Modern Standard
Arabic, French, Russian, Japanese, Korean, Vietnamese, Portuguese, Indonesian,
Bengali, Swahili, Hausa, Yoruba and Amharic. Arabic is rendered right-to-left.
The top-right language button uses a globe icon, shows the current language's
native name when there is room, and keeps the reader on the same page when
switching. It is a dedicated control rather than an item in the mobile "..." menu;
on narrow screens the globe remains and the name is hidden.

## Cloudflare Workers

The workflow in `.github/workflows/docs.yml` builds the site and deploys the
`deepsand-docs` Worker on every push to `master` that changes the docs, the
workflow or the frontend package files. It can also be run manually from the
Actions tab.

The Worker serves the static output from `docs-site/.vitepress/dist` at
<https://deepsand.webslc.com>. Its configuration is `docs-site/wrangler.jsonc`,
and `docs-site/worker.mjs` maps VitePress's clean URLs onto the emitted `.html`
files. Keep the specific `deepsand.webslc.com/*` route beside the custom-domain
entry: the zone also has a `*.webslc.com/*` route on another Worker, which
otherwise shadows this subdomain.

Language routing is handled in `docs-site/worker.mjs`. A first visit to an
English page uses Cloudflare's `request.cf.country` to choose a translated
page when that country has an unambiguous language. The top-right language menu
sets `deepsand_docs_lang` for one year; the Worker honors that cookie ahead of
the IP country, including choosing English. A localized URL entered directly
without a cookie is left alone rather than redirected away.

Required repository secrets:

| Secret | Where to get it |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | Cloudflare dashboard → My Profile → API Tokens. Give it Workers Scripts and Workers Routes edit access for this account; add DNS edit if the custom domain is not already attached. |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare dashboard → account home, visible in the account ID field. |

A local `wrangler login` only authenticates the machine that runs it. GitHub
Actions has no access to that OAuth token, so both repository secrets must be
set or the workflow stops at its configuration check before deploying.

Optional repository variable:

| Variable | Default | Meaning |
| --- | --- | --- |
| `DOCS_SITE_URL` | `https://deepsand.webslc.com` | Public origin used in `sitemap.xml`. Override only when the docs move to another domain. |

To deploy manually:

```bash
npm run docs:build
npx wrangler deploy --config docs-site/wrangler.jsonc
```

VitePress generates `docs-site/.vitepress/dist/sitemap.xml` automatically,
including locale alternates. Keep `DOCS_SITE_URL` aligned with the public origin
or the sitemap will name the wrong host.
