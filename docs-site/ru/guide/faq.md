# Часто задаваемые вопросы

## Видит ли DeepCode мой домашний каталог?

Нет. Песочница видит каталог проекта по адресу `/workspace` и каталоги, которые вы явно предоставляете. Остальная часть файловой системы хоста не смонтирована.

## Что происходит, когда я одобряю запрос каталога?

Deepsand добавляет каталог в качестве разрешения, воссоздает контейнер с новым присоединенным монтированием и возобновляет сеанс DeepCode. Работающая песочница не может получить привязку без повторного создания.

## Где хранятся мои разговоры?

История разговоров, сеансов, вложений и созданных навыков хранятся в томе Docker для каждого проекта. Папка проекта на диске содержит только ваш код и файлы.

Удаление проекта из Deepsand не удаляет этот том. При удалении данных DeepCode проекта том удаляется, но папка проекта остается нетронутой.

## Где хранятся ключи и секреты API?

Неактивные секреты шифруются ключом, хранящимся в хранилище ключей операционной системы, и вводятся в «песочницу» как переменные среды только при ее запуске. Интерфейс показывает имена и длины, а не сохраненные значения.

Учетные данные также могут быть унаследованы от конфигурации вашего хоста DeepCode. Они не копируются в папку проекта.

## Может ли каждый проект использовать другую модель?

Да. Проект может наследовать конфигурацию хоста или переопределить модель, базовый URL-адрес и учетные данные в своих собственных настройках. Селектор заголовка также может выбрать модель для проекта; **Отложить конфигурацию** означает, что проект не закрепил его.

## Какую модель мне следует использовать, чтобы снизить затраты?

Используйте флеш-модель для большинства задач. Deepsand по умолчанию имеет значение `deepseek-v4-flash`, что является более дешевым выбором для повседневного кодирования, пояснений и редактирования. Зарезервируйте `deepseek-v4-pro` для работы, где флэш-память явно не справляется или вам нужны ее дополнительные возможности, поскольку эксплуатация профессиональной модели обходится дороже.

Переключайте модели из шапки проекта или с помощью `/model` в терминале DeepCode. Если вы впервые пробуете Deepsand, начните с флэш-памяти и переходите на версию Pro только тогда, когда у вас есть задача, которая в этом нуждается.

## Что делает слайдер мышления?

Ползунок мышления находится рядом с переключателем модели в заголовке проекта. Он контролирует, сколько рассуждений делает модель, прежде чем дать ответ.

| Стоп | Что это значит |
| --- | --- |
| **Выключенный** | Не думайте, прежде чем ответить. Самый быстрый, но наименее осторожный. |
| **Быстрый** | Немного размышлений, для небольших четко определенных правок. |
| **Сбалансированный** | Умеренное мышление. Средняя остановка и разумное значение по умолчанию для реальной работы. |
| **Глубокий** | Думайте так усердно, как только может модель. Самый медленный и дорогой. |
| **По умолчанию** | Подчинитесь хосту `settings.json`; если он ничего не говорит, DeepCode возвращается к сбалансированному состоянию. |

Для большинства задач оставьте ползунок на **Сбалансированный**. Это средний параметр, и он дает хорошие результаты, не требуя при этом самого медленного и дорогостоящего рассуждения по каждому запросу. Переходите к **Глубокий** только для действительно сложных задач и используйте **Выключенный** или **Быстрый** для небольших, предсказуемых изменений.

## Deepsand работает только с DeepSeek?

Нет. DeepSeek используется по умолчанию, поскольку это модель и конечная точка, с которыми поставляется Deepsand, но Deepsand настраивает DeepCode CLI с использованием имени модели, базового URL-адреса и ключа API. Вы можете указать его на другого провайдера, который предоставляет API, который может вызвать CLI, обычно это конечная точка, совместимая с OpenAI.

Установите базовый URL-адрес и модель поставщика в **Настройки** или в собственных учетных данных проекта и сохраните ключ API этого поставщика в том же месте. Сетевая политика песочницы также должна разрешать конечную точку поставщика.

## Что делать, если Docker Desktop не работает или перестал отвечать на запросы?

Deepsand не может запустить песочницу без движка Docker. Если Docker Desktop не работает, запустите его и подождите, пока двигатель завершит запуск. Deepsand выполняет повторную проверку, когда окно восстанавливает фокус, и полоса состояния предлагает повторную попытку.

Иногда Docker Desktop все еще работает, но его механизм перестает отвечать на запросы. Перезапуск Deepsand этого не исправляет; Сам Docker Desktop необходимо перезапустить.

- **Используйте элемент управления в приложении, когда он появится.** Если Deepsand обнаруживает Docker Desktop, он отображает **Перезапустите Docker Desktop…** в строке состояния или предупреждении терминала. Этот элемент управления перезапускает механизм Docker, включая процесс WSL, который он использует в Windows, и ждет, пока контейнер не сможет запуститься снова.
- **Windows:** щелкните правой кнопкой мыши кит Docker в области уведомлений и выберите **Перезапуск**. Если эта опция отсутствует, откройте Docker Desktop, выберите **Устранение неполадок**, затем **Перезагрузить Docker Desktop**.
- **macOS:** щелкните кит Docker в строке меню и выберите **Перезапуск**.
- **Linux:** откройте меню Docker Desktop, выберите **Устранение неполадок**, затем **Перезагрузить Docker Desktop**. Если вы используете Docker Engine вместо Docker Desktop, перезапустите его службу, например `sudo systemctl restart docker`.

Перезапуск Docker Desktop завершает работу каждого контейнера на компьютере, включая контейнеры, не связанные с Deepsand. Deepsand предлагает перезагрузку, но не делает это автоматически. См. [Документация по устранению неполадок Docker](https://docs.docker.com/desktop/troubleshoot-and-support/troubleshoot/) для меню для конкретной платформы.

## Могу ли я использовать Deepsand без доступа в Интернет?

Модель нуждается в конечной точке. В сетевом режиме `none` только эта конечная точка доступна через прокси-сервер Deepsand. Установка пакетов и другой доступ к сети не удастся, если вы не разрешите нужные им хосты.

## Как обновить Deepsand?

Откройте **Настройки**, затем **Обновления** и проверьте наличие более новой версии. Выпускные сборки загружают подписанные обновления и перезапускают приложение после их установки. Установка обновления останавливает запуск песочниц.

## Есть ли интерфейс командной строки?

Да. `deepsandctl` предоставляет такие команды без заголовка, как `doctor`, `plan`, `run`, `watch`, `requests` и `network`. Настольное приложение и CLI используют один и тот же код политики в `deepsand-core`.

## Как сообщить о проблеме безопасности?

Не открывайте публичную публикацию из-за проблем с безопасностью. Свяжитесь с сопровождающими лично через канал отчетов о безопасности репозитория и сообщите достаточно подробностей, чтобы воспроизвести проблему.
