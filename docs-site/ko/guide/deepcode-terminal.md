# DeepCode 터미널 사용

Deepsand는 샌드박스 내부에서 [DeepCode CLI](https://github.com/lessweb/deepcode-cli)를 실행합니다. **단말기** 탭은 라이브 DeepCode 세션입니다. 일반 언어로 요청을 입력하거나 DeepCode의 슬래시 명령 중 하나를 사용하여 세션을 제어합니다.

자신의 컴퓨터에 DeepCode를 설치하지 않습니다. Deepsand는 프로젝트 컨테이너에서 CLI를 시작합니다. 여기서 `/workspace` 및 공유한 디렉터리를 볼 수 있습니다.

[DeepCode 프로젝트 홈페이지](https://deepcode.vegamo.cn/) 또는 [DeepCode 저장소](https://github.com/lessweb/deepcode-cli)에 대해 자세히 알아보세요.

## 세션 시작

1. 사이드바에서 프로젝트를 선택합니다.
2. **달리다**를 누르세요.
3. 샌드박스가 시작될 때까지 기다립니다. 이미지가 누락된 경우 Deepsand는 먼저 이미지를 빌드하고 **활동**에 빌드 출력을 표시합니다.
4. CLI가 준비되면 DeepCode 터미널이 나타납니다.

샌드박스를 중지하면 컨테이너가 종료됩니다. 프로젝트를 다시 시작하면 이전 DeepCode 대화가 있으면 다시 시작됩니다.

## DeepCode에게 작업을 요청하세요.

일반 요청을 입력하고 **입력하다**를 누르세요. 예를 들어:

```text
Find the failing test in this project and explain what is wrong.
```

DeepCode는 작업 공간에서 파일을 읽고 편집하고, 명령을 실행하고, 프로젝트에 대해 선택된 도구를 사용할 수 있습니다. 제어권을 유지하세요. 작업 공간 외부에 무언가가 필요할 때 Deepsand는 샌드박스를 일시 중지하고 먼저 묻습니다.

## 기본 슬래시 명령

슬래시 명령은 `/`로 시작됩니다. `/`를 단독으로 입력하면 명령 메뉴가 열립니다.

| 명령 | 그것이 하는 일 |
| --- | --- |
| `/new` | 새로운 대화를 시작하세요 |
| `/resume` | 계속하려면 이전 대화를 선택하세요 |
| `/fork` | 현재 대화 포크 |
| `/continue` | 활성 대화를 계속하거나 재개할 대화를 선택하세요 |
| `/model` | 모델, 사고 모드 및 추론 노력 전환 |
| `/raw` | 디스플레이 모드 전환: Normal, Lite 또는 Raw 스크롤백 |
| `/init` | 프로젝트 지침이 포함된 `AGENTS.md` 파일 만들기 |
| `/skills` | DeepCode에서 사용할 수 있는 기술 목록 |
| `/mcp` | MCP 서버 상태 및 사용 가능한 도구 표시 |
| `/undo` | 코드, 대화 또는 둘 다를 이전 지점으로 복원 |
| `/exit` | DeepCode 종료 |

프로젝트에는 이미 `AGENTS.md`가 있을 수 있습니다. `/init`를 사용하기 전에 확인하여 이미 있는 지침을 교체하지 마십시오.

## 키보드 단축키

| 열쇠 | 액션 |
| --- | --- |
| `Enter` | 프롬프트 보내기 |
| `Shift+Enter` | 개행 삽입 |
| `Ctrl+J` | 개행 삽입 |
| `Esc` | 현재 모델 회전 중단 |
| `Ctrl+V` | 선택한 모델이 이미지를 지원하는 경우 이미지 붙여넣기 |
| `Ctrl+D` 두 번 | DeepCode 종료 |

`Esc`로 회전을 중단한 후 다른 요청을 입력할 수 있습니다. 샌드박스가 다시 시작되지 않습니다.

## 터미널에 파일 놓기

파일을 터미널로 드래그하면 해당 경로가 입력됩니다.

- 프로젝트 폴더 내부 또는 프로젝트와 공유한 디렉토리 내부의 파일은 샌드박스가 이미 볼 수 있는 위치(`/workspace/...` 또는 `/grants/...`)를 참조합니다. 아무것도 복사되지 않습니다.
- 다른 곳의 파일이 샌드박스 내부의 `/tmp/deepsand-incoming`에 복사되고 Deepsand가 먼저 묻습니다. 해당 폴더는 저장소의 일부가 아니므로 삭제된 파일은 커밋으로 끝날 수 없으며 샌드박스가 다시 생성되면 사라집니다. 대화 상자에는 **설정 → 동작 → 프로젝트 외부에서 파일을 삭제하기 전에 경고**와 동일한 설정인 **다시는 경고하지 않음** 스위치가 있습니다.

## 최신 상태 유지

DeepCode CLI는 샌드박스 이미지 내부에 설치되며 샌드박스는 자체적으로 업데이트할 수 없습니다. 시작할 때마다 Deepsand는 npm에게 최신 릴리스가 무엇인지 묻고, 이미지에 이전 릴리스가 있는 경우 먼저 이미지의 해당 부분을 다시 빌드합니다. 따라서 이미 업데이트를 요청하는 버전에서는 터미널이 열리지 않습니다. 답변은 15분 동안 기억되므로 이는 실행당 하나가 아닌 하나의 요청이며 npm에 도달할 수 없는 경우 샌드박스는 이미 있는 버전에서 시작됩니다.

## 세션, 모델 및 실행 취소

- `/new`는 깔끔한 대화로 다시 시작합니다. 프로젝트 파일은 삭제되지 않습니다.
- `/resume` 및 `/continue`는 이전 대화를 다시 가져옵니다.
- `/model`는 세션의 모델, 사고 모드 및 추론 노력을 변경합니다. 프로젝트 헤더에는 모델 선택기와 사고 슬라이더도 있습니다. **균형 잡힌**는 중간 정지점이며 대부분의 작업에 권장되는 설정입니다.
- `/undo`는 코드, 대화 또는 둘 다를 이전 지점으로 복원합니다. 원하지 않는 변경 사항을 취소하는 가장 빠른 방법입니다.

대화 기록은 저장소가 아닌 프로젝트의 Deepsand 상태 볼륨에 있습니다.

## 권한 및 샌드박스

터미널은 컨테이너 내부에 있으므로 `/workspace`의 프로젝트와 명시적으로 공유한 디렉터리만 볼 수 있으며 컴퓨터의 다른 항목은 볼 수 없습니다.

DeepCode가 다른 디렉터리, 네트워크 대상, 도구 또는 다른 리소스를 요청하면 Deepsand는 샌드박스를 정지하고 권한 대화 상자를 표시합니다.

- **액세스 권한 부여**는 요청을 적용하고 세션을 재개합니다.
- **지금은 아님**는 이번에는 이를 거부했습니다. DeepCode는 나중에 다시 요청할 수 있습니다.
- **다시 묻지 마세요**는 이를 거부하고, Deepsand는 말로만 거부하는 것이 아니라 해당 경로(및 그 아래의 모든 것) 또는 해당 호스트(및 하위 도메인) 자체를 거부합니다. 모든 블록은 권한에 나열되어 있으며 여기서 다시 해제할 수 있습니다.
- 디렉터리를 승인하면 새 탑재로 컨테이너가 다시 생성됩니다.

민감한 파일이 포함된 디렉토리를 공유하기 전에 [샌드박스 작동 방식](./security)를 읽으십시오.

## 터미널이 시작되지 않는 경우

- **이미지가 없습니다:** Deepsand가 먼저 빌드합니다. 빌드 진행 상황은 **활동**를 시청하세요.
- **Docker Desktop가 실행되지 않거나 중단되었습니다.**를 시동하고 엔진 시동이 완료될 때까지 기다립니다. Docker Desktop가 실행 중이지만 엔진이 응답하지 않는 경우 Docker Desktop를 다시 시작하세요. Deepsand가 표시되면 앱 내 **Docker Desktop를 다시 시작하세요...** 컨트롤을 사용하세요. 그렇지 않으면 Windows에서 알림 영역의 Docker 고래를 마우스 오른쪽 버튼으로 클릭하고 **다시 시작**를 선택합니다. macOS에서는 Docker 메뉴 표시줄 아이콘을 사용합니다. Linux에서 Docker Desktop의 **문제 해결** 메뉴를 엽니다. Docker Desktop를 다시 시작하면 머신의 모든 컨테이너가 종료됩니다. [Docker FAQ](./faq#what-if-docker-desktop-is-not-running-or-has-stopped-responding)를 참조하세요.
- **API 키가 누락되었거나 거부되었습니다.** **설정**를 열고 유효한 키를 저장하세요.
- **DeepCode 종료:** **달리다**를 다시 누르세요. `/resume`를 사용하여 이전 세션을 재개할 수 있습니다.
