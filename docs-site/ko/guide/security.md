# 샌드박스 작동 방식

간단히 말하면, 보조자는 귀하가 선택한 프로젝트와 귀하가 승인한 폴더에서 작업할 수 있으며 컴퓨터의 다른 곳에서는 작업할 수 없습니다.

Deepsand의 약속은 좁고 테스트 가능합니다. 샌드박스는 프로젝트 디렉터리와 명시적으로 부여한 디렉터리에만 접근할 수 있으며 그 외에는 아무 것도 할 수 없습니다.

## 경계

컨테이너에는 Deepsand가 선택한 바인드 마운트 이외의 호스트 파일 시스템에 대한 보기가 없습니다. 컨테이너의 마운트 네임스페이스 내에 다른 호스트 경로가 존재하지 않으므로 이스케이프할 호스트 파일이 없습니다.

여기에 설명된 다른 모든 내용은 해당 경계를 넘어서는 심층적인 방어입니다.

## 시행되는 사항

- 작업공간과 명시적 권한 부여만 호스트에서 마운트됩니다.
- 응답 스풀과 상태 디렉터리는 읽기 전용으로 마운트됩니다.
- 컨테이너 런타임 소켓은 이름으로 거부됩니다.
- 컨테이너 루트 파일 시스템은 읽기 전용이며 `/tmp` 및 `/run`에 대한 크기의 임시 파일 시스템이 있습니다.
- 경로를 확인하기 전에 기호 링크가 확인되므로 링크는 금지된 대상을 위장할 수 없습니다.
- DeepCode가 실행되기 전에 권한이 삭제되고 `no-new-privileges`는 해당 권한을 다시 얻을 수 없도록 방지합니다.

## 네트워크 모드

| 모드 | 그것이 허용하는 것 |
| --- | --- |
| 없음 | Deepsand 프록시를 통한 모델 엔드포인트만 가능합니다. |
| 허용 목록 | 모델 엔드포인트, 프록시, 허용 목록의 호스트 또는 주소입니다. |
| 인터넷 | 컨테이너 내부에서 로컬 및 개인 범위가 차단된 인터넷 액세스. |
| 전체 | 로컬 네트워크 차단 없이 인터넷에 액세스할 수 있습니다. 샌드박스에 로컬 네트워크가 꼭 필요한 경우에만 사용하세요. |

허용 목록에 있는 호스트 이름은 프록시를 통과하여 이름 자체를 확인하고 개인 주소 공간에서 결과를 거부합니다. 데이터베이스 클라이언트 또는 HTTP가 아닌 다른 프로그램은 프록시를 사용할 수 없기 때문에 허용 목록에 있는 주소는 컨테이너 규칙에 의해 직접 허용됩니다. 항목에 이름이 지정된 포트는 호스트의 루프백에도 게시되며 모든 인터페이스에는 게시되지 않습니다.

## 당신이 결정하는 것

Deepsand는 자동으로 액세스 권한을 부여하지 않습니다. 요청은 요청하는 경로, 호스트, 도구 또는 리소스와 함께 사용자에게 도달하며 샌드박스는 사용자가 결정할 때까지 일시 중지된 상태로 유지됩니다.

샌드박스에 이미 있는 항목에 대한 요청은 설명과 함께 거부됩니다. 자동 허용은 사용자가 제공하지 않은 동의이기 때문입니다. 모호한 모든 것이 당신에게 도달합니다.

## 보호하지 못하는 것

- 모델 제공자는 귀하가 보내는 콘텐츠를 볼 수 있습니다.
- 작업 공간에 배치한 파일은 샌드박스에 표시되며 변경되거나 삭제될 수 있습니다.
- 잘못된 도구나 모델 지침은 여전히 ​​액세스를 요청할 수 있습니다. 결정은 귀하의 것입니다.
- Docker 자체가 경계 외부에 있습니다. Docker Desktop 및 호스트 운영 체제를 업데이트된 상태로 유지하세요.
