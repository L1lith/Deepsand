# 자주 묻는 질문

## DeepCode는 내 홈 디렉토리를 볼 수 있나요?

아니요. 샌드박스는 `/workspace`의 프로젝트 디렉터리와 명시적으로 부여한 디렉터리를 확인합니다. 호스트 파일 시스템의 나머지 부분은 마운트되지 않습니다.

## 디렉토리 요청을 승인하면 어떻게 되나요?

Deepsand는 디렉터리를 권한 부여로 추가하고 새 마운트가 연결된 컨테이너를 다시 생성한 다음 DeepCode 세션을 재개합니다. 실행 중인 샌드박스는 다시 생성되지 않고는 바인드 마운트를 얻을 수 없습니다.

## 내 대화는 어디에 저장되나요?

대화 기록, 세션, 첨부 파일 및 생성된 기술은 프로젝트별 Docker 볼륨에 저장됩니다. 디스크의 프로젝트 폴더에는 코드와 파일만 포함됩니다.

Deepsand에서 프로젝트를 제거해도 해당 볼륨은 삭제되지 않습니다. 프로젝트의 DeepCode 데이터를 지우면 볼륨은 제거되지만 프로젝트 폴더는 그대로 유지됩니다.

## API 키와 비밀은 어디에 저장됩니까?

비밀은 운영 체제의 키 저장소에 보관된 키를 사용하여 저장 중에 암호화되며 시작될 때만 환경 변수로 샌드박스에 주입됩니다. 인터페이스에는 이름과 길이가 표시되며 저장된 값은 표시되지 않습니다.

자격 증명은 호스트 DeepCode 구성에서 상속될 수도 있습니다. 프로젝트 폴더에는 복사되지 않습니다.

## 각 프로젝트에서 다른 모델을 사용할 수 있나요?

예. 프로젝트는 호스트 구성을 상속하거나 자체 설정에서 모델, 기본 URL 및 자격 증명을 재정의할 수 있습니다. 헤더 선택기는 프로젝트의 모델을 선택할 수도 있습니다. **구성으로 연기**는 프로젝트가 하나를 고정하지 않았음을 의미합니다.

## 비용을 낮추려면 어떤 모델을 사용해야 합니까?

대부분의 작업에 플래시 모델을 사용하십시오. Deepsand의 기본값은 `deepseek-v4-flash`로, 일상적인 코딩, 설명 및 편집에 가장 저렴한 선택입니다. 플래시가 확실히 어려움을 겪고 있거나 추가 기능이 필요한 작업을 위해 `deepseek-v4-pro`를 예약하세요. 프로 모델은 실행 비용이 더 많이 들기 때문입니다.

프로젝트 헤더에서 또는 DeepCode 터미널의 `/model`를 사용하여 모델을 전환하세요. Deepsand를 처음 시도하는 경우 플래시로 시작하고 필요한 작업이 있을 때만 프로로 전환하세요.

## 사고 슬라이더는 무엇을 합니까?

생각 슬라이더는 프로젝트 헤더의 모델 선택기 옆에 있습니다. 모델이 응답하기 전에 얼마나 많은 추론을 수행하는지 제어합니다.

| 중지 | 의미 |
| --- | --- |
| **끄다** | 대답하기 전에 생각하지 마십시오. 가장 빠르지만 가장 조심스럽지 않습니다. |
| **빠른** | 잘 지정된 작은 편집에 대해서는 약간의 생각이 필요합니다. |
| **균형 잡힌** | 적당한 사고. 실제 작업을 위한 중간 중지 및 합리적인 기본값입니다. |
| **깊은** | 모델이 할 수 있는 한 열심히 생각하십시오. 가장 느리고 가장 비쌉니다. |
| **기본** | 호스트 `settings.json`로 연기합니다. 아무 말도 하지 않으면 DeepCode는 Balanced로 돌아갑니다. |

대부분의 작업에서는 슬라이더를 **균형 잡힌**에 유지하세요. 중간 설정이며 모든 요청에 ​​대해 가장 느리고 가장 비용이 많이 드는 추론 비용을 지불하지 않고도 좋은 결과를 제공합니다. 정말 어려운 문제인 경우에만 **깊은**로 이동하고, 작고 예측 가능한 편집인 경우에는 **끄다** 또는 **빠른**를 사용하세요.

## Deepsand는 DeepSeek에서만 작동합니까?

아니요. DeepSeek은 Deepsand와 함께 제공되는 모델 및 엔드포인트이기 때문에 기본값이지만 Deepsand는 모델 이름, 기본 URL 및 API 키를 사용하여 DeepCode CLI를 구성합니다. CLI가 호출할 수 있는 API(일반적으로 OpenAI 호환 엔드포인트)를 노출하는 다른 공급자를 가리킬 수 있습니다.

**설정** 또는 프로젝트 자체 자격 증명에 공급자의 기본 URL과 모델을 설정하고 해당 공급자의 API 키를 동일한 위치에 저장합니다. 샌드박스의 네트워크 정책은 공급자의 엔드포인트도 허용해야 합니다.

## Docker Desktop가 실행되지 않거나 응답을 중지하면 어떻게 되나요?

Deepsand는 Docker 엔진 없이 샌드박스를 시작할 수 없습니다. Docker Desktop가 실행되고 있지 않으면 시동을 걸고 엔진 시동이 완료될 때까지 기다리십시오. Deepsand는 창이 초점을 다시 얻었을 때 다시 확인하고 상태 표시줄은 재시도를 제공합니다.

때로는 Docker Desktop가 계속 실행 중이지만 엔진이 응답을 멈춘 경우가 있습니다. Deepsand를 다시 시작해도 문제가 해결되지 않습니다. Docker Desktop 자체를 다시 시작해야 합니다.

- **인앱 컨트롤이 나타나면 사용하세요.** Deepsand가 Docker Desktop를 감지하면 상태 표시줄이나 터미널 경고에 **Docker Desktop를 다시 시작하세요...**가 표시됩니다. 해당 컨트롤은 Windows에서 사용하는 WSL 프로세스를 포함하여 Docker 엔진을 다시 시작하고 컨테이너가 다시 시작될 때까지 기다립니다.
- **Windows:** 알림 영역에서 Docker 고래를 마우스 오른쪽 버튼으로 클릭하고 **다시 시작**를 선택합니다. 해당 옵션이 없으면 Docker Desktop를 열고 **문제 해결**를 선택한 다음 **Docker Desktop 다시 시작**를 선택합니다.
- **macOS:** 메뉴 표시줄에서 Docker 고래를 클릭하고 **다시 시작**를 선택합니다.
- **Linux:**는 Docker Desktop 메뉴를 열고 **문제 해결**를 선택한 다음 **Docker Desktop 다시 시작**를 선택합니다. Docker Desktop 대신 Docker Engine를 사용하는 경우 해당 서비스(예: `sudo systemctl restart docker`)를 다시 시작하세요.

Docker Desktop를 다시 시작하면 Deepsand와 관련되지 않은 컨테이너를 포함하여 머신의 모든 컨테이너가 종료됩니다. Deepsand는 재시작을 제공하지만 자동으로 수행하지는 않습니다. 플랫폼별 메뉴는 [Docker의 문제 해결 문서](https://docs.docker.com/desktop/troubleshoot-and-support/troubleshoot/)를 참조하세요.

## 인터넷 접속 없이 Deepsand를 사용할 수 있나요?

모델에는 끝점이 필요합니다. `none` 네트워크 모드에서는 Deepsand 프록시를 통해 해당 엔드포인트에만 연결할 수 있습니다. 필요한 호스트를 허용하지 않으면 패키지 설치 및 기타 네트워크 액세스가 실패합니다.

## Deepsand를 어떻게 업데이트하나요?

**설정**를 연 다음 **업데이트**를 열고 최신 버전을 확인하세요. 릴리스 빌드는 서명된 업데이트를 다운로드하고 설치 후 앱을 다시 시작합니다. 업데이트를 설치하면 샌드박스 실행이 중지됩니다.

## 명령줄 인터페이스가 있나요?

예. `deepsandctl`는 `doctor`, `plan`, `run`, `watch`, `requests` 및 `network`와 같은 헤드리스 명령을 제공합니다. 데스크톱 앱과 CLI는 `deepsand-core`에서 동일한 정책 코드를 공유합니다.

## 보안 문제를 어떻게 신고하나요?

보안 문제로 인해 공개 문제를 열지 마십시오. 저장소의 보안 보고 채널을 통해 관리자에게 개인적으로 연락하고 문제를 재현할 수 있는 충분한 세부 정보를 포함하십시오.
