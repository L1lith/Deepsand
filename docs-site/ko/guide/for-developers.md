# 후드 아래

이 페이지는 시스템의 기술적 형태를 원하는 개발자를 위한 것입니다. 일반 언어 설명을 찾고 있다면 [Deepsand란 무엇입니까?](./what-is-deepsand)로 시작하세요.

## 건축학

Deepsand는 세 가지 주요 레이어로 구성된 Tauri 데스크톱 앱입니다.

- **창문**는 SolidJS 인터페이스입니다. 상태를 렌더링하고 의도를 보냅니다. 그것은 정책을 결정하지 않습니다.
- **타우리층**는 데스크톱 명령을 노출하고 동일한 명령 표면을 원격 클라이언트용 루프백 HTTP 서버로 변환합니다.
- **`deepsand-core`**가 규칙을 소유합니다. 경로 유효성 검사, `docker run` 계획, 권한 브로커, 송신 프록시, 암호화된 비밀 저장소 및 상태 저장소가 모두 여기에 있습니다.

데스크탑 앱과 명령줄 드라이버 `deepsandctl`는 동일한 코어를 사용하므로 보안 결정 시 서로 분리될 수 없습니다.

## 하나의 프로젝트, 하나의 컨테이너

각 프로젝트는 자체 Docker 컨테이너와 자체 상태 볼륨을 갖습니다. 프로젝트 디렉토리는 `/workspace`에 마운트됩니다. 다른 호스트 디렉터리에는 명시적인 권한 부여가 필요합니다.

`policy::plan_run`는 완전한 `docker run` argv를 한곳에 구축합니다. 활동 탭에는 마운트, 기능, 네트워크 모드 및 읽기 전용 경로를 포함한 정확한 계획이 표시됩니다.

컨테이너는 의도적으로 제한됩니다.

- 루트 파일 시스템은 읽기 전용이며 `/tmp` 및 `/run`에 대한 크기의 tmpfs 마운트가 있습니다.
- 응답 스풀과 상태 디렉터리는 읽기 전용으로 마운트됩니다.
- 컨테이너 런타임 소켓은 이름으로 거부됩니다.
- DeepCode가 실행되기 전에 기능이 삭제되고 `no-new-privileges`가 설정됩니다.
- 컨테이너 런타임 소켓 및 기타 금지된 마운트는 더 약한 계획을 생성하는 대신 페일클로즈됩니다.

## 권한

샌드박스는 추가 액세스를 요청할 수 있지만 이를 승인할 수는 없습니다. 권한 요청은 스풀에 기록됩니다. 호스트 브로커는 이를 검증하고 컨테이너를 일시 중지합니다. 운영자는 요청을 보고 결정합니다.

디렉터리 요청을 승인하면 새 바인드 마운트로 컨테이너가 다시 생성되고 세션이 재개됩니다. 거부는 최종적이며 모델에 보고됩니다.

샌드박스에 이미 있는 항목에 대한 요청은 설명과 함께 거부됩니다. 자동 승인 경로는 없습니다. 자동 승인은 운영자가 제공하지 않은 동의이기 때문입니다.

## 네트워킹

네트워크 정책에는 네 가지 모드가 있습니다.

| 모드 | 행동 |
| --- | --- |
| `none` | Deepsand 송신 프록시를 통한 모델 엔드포인트만. |
| `allowlisted` | 모델 엔드포인트, 프록시, 명명된 호스트, 주소 및 포트. |
| `internet` | 컨테이너 내부에서 로컬 및 개인 범위가 차단된 인터넷 액세스. |
| `full` | 로컬 네트워크 차단 없이 인터넷에 액세스할 수 있습니다. |

호스트 이름 항목은 비공개, 루프백, 링크 로컬 및 예약된 결과를 거부하는 프록시에 의해 확인됩니다. 주소 항목은 컨테이너에 의해 직접 적용되며, 이를 통해 데이터베이스 클라이언트 또는 기타 HTTP가 아닌 프로그램이 연결할 수 있습니다. 명명된 포트는 호스트 루프백에만 게시됩니다.

## 비밀 및 업데이트

보안 비밀은 운영 체제 키 저장소에 보관된 키를 사용하여 저장 시 암호화됩니다. 명령줄 값이 아닌 환경 파일을 통해 컨테이너에 전달되며 샌드박스가 시작될 때만 삽입됩니다.

릴리스 빌드는 서명된 업데이트를 설치하기 전에 확인합니다. 서명 키는 저장소에 저장되지 않습니다.

## 명령줄

`deepsandctl`는 헤드리스 표면을 제공합니다.

```bash
deepsandctl doctor
deepsandctl plan <project> --offline
deepsandctl run <project>
deepsandctl watch <project>
deepsandctl requests <project>
deepsandctl network <project> <mode>
```

`plan --offline`는 컨테이너를 시작하지 않고 정확한 `docker run` argv를 인쇄합니다. 이는 변경된 정책을 검토하는 데 유용합니다.
