# The Cleanup Update

A permission answer could freeze the window and return after every restart, and sandboxes could
outlive the app that started them. Both are fixed, and the second now cleans up after itself
while the app runs.

## Granting a secret no longer freezes the app

When the agent asked for a secret, pressing **Grant access** could leave the whole window frozen
with the busy cursor, and the same dialog came back after every restart. Two bugs in one path
caused it:

- the answer took the app's state lock a second time on the same thread. A lock cannot be taken
  twice that way — it waits for itself — and the command ran on the UI thread, so the window
  stopped painting and never came back;
- the secret path never removed the answered request from the spool, so the next tick, and the
  next launch, announced the same decision again, with the sandbox paused behind it.

Now the secret is stored, the answer is written, the request is cleared, and the command runs off
the UI thread. If the value cannot be stored — a locked keystore, a reserved name — you get a
refusal that says why, and the model is told the same thing, instead of a dialog that never
resolves.

A request that already has an answer is also no longer shown again after a restart. The answer is
the truth; the leftover request is dropped.

## Sandboxes clean up after themselves

**Activity → Containers** now lists every container Deepsand created, with its Docker state, its
project, and whether a session owns it. A container no session owns — from a crash, a failed
start, or an old probe — is removed automatically once it is past a short grace period, and the
list is re-read every minute. **Remove abandoned** does the same on demand.

A container is only removed when all of these are true: no live session owns it, no start is in
flight for its project, and it is older than two minutes. A running sandbox, a sandbox that is
starting, and a container younger than that are never touched, and neither is anything Docker
holds that Deepsand did not create.

A container is a running session, not a project. Your project's files and its conversation live
in the folder you chose and a state volume, and this cleanup never touches either.

## Smaller things

- The documentation now shows a real screenshot of the app in each of its seventeen languages.
- Intel Mac builds are in the update manifest again: the release pipeline passes the target to
  every matrix job, so the two macOS builds no longer collide on one artifact name.
- The translator refuses to write a page whose markup it changed, rather than producing a page
  that cannot render.

## Upgrading

If your sandbox image was built from an earlier runtime revision, the first Run of each project
rebuilds it once. Deepsand does that automatically, and the build output appears in the Activity
tab.
