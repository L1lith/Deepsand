# DeepCode 0.7.0, Terminal Newlines, and Docker Memory

## DeepCode 0.7.0

DeepCode 0.7.0 reworded the idle half of its prompt footer (`esc to interrupt · ctrl+c to
cancel input` became `enter queue · esc interrupt`). Deepsand's footer patch matches the shape
it was written against, so it refused the new bundle and the runtime image build failed — with
the misleading result that a project could not start at all. The patch now knows both wordings,
still refuses one it has not been checked against, and keeps a long command's footer to a
single line. The Ink renderer and `@`-mention patches apply and verify against 0.7.0
unchanged.

## Newlines in the terminal

Shift+Enter now inserts a newline, and pasting a multi-line block inserts it as one block
instead of one submitted line per line.

Both failed for the same kind of reason: the terminal is a ConPTY, which does not carry the
usual encodings through. DeepCode recognises the CSI-u shift+return sequence only when it is
the whole read, and ConPTY batches it with the text just typed; the bracketed-paste markers
are consumed by the console host, along with the line endings inside them. The terminal now
sends Shift+Enter as the byte for Ctrl+J — a newline in the CLI's input box — and sends a
pasted block as LF-terminated text, which DeepCode's input dispatcher splits and turns into
newlines. Tabs in a pasted block are expanded to four spaces, and escape and control
characters are removed, as the CLI's own paste path does. A very large paste is inserted
verbatim rather than collapsed to `[paste #N +N lines]`, because that marker cannot survive
this terminal.

## Docker Desktop memory failures

When Docker Desktop's Hyper-V VM cannot start, it closes and the next attempt fails the same
way. The engine's own log carries the reason — usually that the machine did not have enough
free memory for the VM — and Deepsand now reads it and says so, instead of "Docker Desktop is
not running. Start it and try again."

`deepsandctl doctor` reports host memory, Docker Desktop's configured VM memory and swap, a
live headroom verdict, and the last engine-start memory failure with its timestamp and log
path. The app's memory message is translated into every supported language.

Deepsand also builds one runtime image at a time now. Two images' worth of apt, npm and cargo
is the memory peak the app itself creates, and a build that takes the VM down with it looks
like Docker Desktop crashing. A build that has to wait says so in its log.

## Upgrading

The runtime revision changed with the footer patch, so the next Run rebuilds this project's
image; the previous image is swept after the grace period. Project files, grants, approved
packages and conversation volumes are not modified.
