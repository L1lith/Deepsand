# Docker Desktop Recovery and Permission Tools

This release is about the two places that were still rough: Docker Desktop when its file
sharing wedges, and the project window's small everyday actions.

## Docker Desktop recovery

A start that failed because Docker Desktop had stopped answering used to leave you with an
error box that just told you to restart Docker. The box now offers **Restart Docker Desktop
and retry** directly, and the same action is still available on the terminal tab. Restarting
Docker still ends every container on the machine, so it remains your decision; the app only
puts the control where you already are.

Starts that no button asked for — the automatic restart after an unexpected exit and the
resume-on-launch — now show the **Starting** state for as long as the backend holds the start
lock. Before, the Run buttons could look idle while the backend answered "already starting."
Their failures also reach the window instead of only the log.

The terminal's busy footer is kept to one line. A multiline command used to make the footer
taller than the viewport, which pushed the input box off the top of the screen; the command is
now collapsed to a single line and `esc to interrupt` stays in front of it.

## Stale Docker Desktop file shares

Docker Desktop records every bind-mount source in its per-user file-sharing list and never
removes an entry when the path disappears. Those dead entries do not grant the sandbox
anything, but the gRPC FUSE watcher still tracks them, and a long list makes Docker Desktop's
known Hyper-V watcher hang more likely.

`deepsandctl doctor` now reports the configured and missing counts. The new
`deepsandctl docker-shares --prune` lists the stale entries and removes **only paths that no
longer exist**, after copying `settings-store.json` to a timestamped backup and stopping and
restarting Docker Desktop. Existing paths — projects and grants — are never removed. This
reduces one trigger; it does not change the Docker Desktop bug itself.

## Copy permission paths

In **Permissions → Inside sandbox**, both the **Reachable at** and **Host path** fields now
have a copy button. Right-clicking anywhere over either path copies it as well. This works for
the workspace row and for every shared folder.

## Open with Code

Right-clicking a project in the sidebar now offers **Open with Code** when the host's `code`
command is on PATH. The check is made when the app starts and again whenever the menu opens,
so installing VS Code does not require restarting Deepsand. The action is desktop-only and is
not exposed to remote clients.

## Upgrading

The runtime revision changed with the terminal-footer patch, so the next Run rebuilds this
project's image; the previous image is swept after the grace period. Project files, grants,
approved packages and conversation volumes are not modified. If Docker Desktop itself is
currently wedged, use the new restart action or `deepsandctl docker-shares --prune` before
starting the project again.
