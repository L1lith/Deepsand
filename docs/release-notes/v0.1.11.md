# The Reliability Update

A crash no longer costs you the project list, refusing something now means what it says, and the
contained DeepCode CLI is brought up to date before every start rather than asking you to update
it from inside the terminal.

## Recovery that actually recovers

Deepsand already wrote its state atomically and kept a rolling backup. But a state file with
invalid bytes was classified as *unreadable*, and unreadable meant stop — before the backup was
ever tried. One bad write emptied the window while a perfectly good copy sat beside it.

- Bytes that are not text are now treated as damage, not as an I/O error, so the recovery chain
  runs: live file → rolling backup → the staged write of an interrupted save → dated snapshots →
  anything set aside earlier.
- The rolling backup and the daily snapshot are only made from a copy that parses, so a damaged
  file can no longer be promoted into the backup and take the last good copy with it.
- When nothing can be read at all, the fallback no longer rotates the backup: the next launch
  still has something to recover from.

## Two kinds of refusal

Rejecting a permission request used to be one button that permanently blocked the path. There are
now two, and the model is told which answer it received:

- **Not now** — declined this time; it may ask again later.
- **Don't ask again** — refused for good.

## Refusals the host enforces

"Don't ask again" is no longer something the agent is politely told to respect:

- A refused directory is blocked together with **everything beneath it**, and the block is
  enforced where mounts are created — a blocked path never becomes reachable at all.
- A refused destination is blocked together with **its subdomains**, and becomes a deny rule the
  egress proxy enforces.
- Every block is listed under **Permissions → Blocked**, with **Allow again**. A permanent
  refusal with no way back would be a trap, not a decision.

In Internet and Full network modes there is no proxy, so a host block there prevents the
destination ever being granted but cannot refuse the connection itself. The Permissions tab says
exactly that rather than implying more.

## Secrets that are actually saved

The secret request dialog had no fields for the secret: it showed the request under "Tools
requested", sent whatever the model had suggested, and closed silently when the host refused.
It now asks for a name and a value, calls them a secret, saves them, and tells you when
something was not applied.

## Dropping files into the terminal

- From a directory the project already sees — the project folder **or a shared one** — the file
  is named where the sandbox sees it (`/workspace/...`, `/grants/...`) and nothing is copied.
  Files dropped from shared directories used to be copied under a timestamped name instead.
- From anywhere else, Deepsand warns first, with a **Don't warn me again** switch that also
  appears in Settings → Behaviour. Confirmed files go to `/tmp/deepsand-incoming`, outside every
  mount, so a file dragged in for one question cannot end up in a commit and disappears with the
  sandbox.

## A current DeepCode CLI

The CLI lives in the sandbox image, and the sandbox cannot install its own update — so an image
built weeks ago opened the terminal on a version that immediately asked to update itself from a
place where that is impossible.

Before each start Deepsand now asks npm for the latest release, compares it with what the image
carries, and rebuilds that one layer first when they differ. The answer is remembered for fifteen
minutes, so this is one request rather than one per run, and a registry that cannot be reached
means the sandbox starts on the version already installed instead of failing to start.

## Nothing installed until you ask

A new project quietly installed `git`, `jq`, `ripgrep`, `curl`, `zip` and `htmlq`, because "no
stored selection" was read as "the old default list". It now means what the Tools tab always said:
**nothing is enabled**. Projects created earlier keep their selection, so their existing image
still runs unchanged.

The Tools tab's sections are ordered **Capabilities, Languages, Package managers, Utilities,
Reverse Engineering**.

## Upgrading

The sandbox image changed in this release, so the first Run of each project rebuilds it once. A
new project now starts from an image with no tools at all, which builds faster than the old
default and installs only what you choose.
