# The Steady Terminal Update

Two things that made the app feel stuck: a terminal that could still start scrolling itself,
and a Stop that could sit on "Stopping…" with nothing happening. Both are fixed.

## The terminal's second cause

0.1.13 stopped the pseudo-terminal being **born** the wrong size: the pane's size is remembered
per project and the PTY is created at it. That was real, and it was not the whole story.

`docker run -t` asks the terminal for a cursor position as soon as the PTY exists, and **waits
for the answer**. xterm answers immediately — but the answer arrives through `write_to_session`
a moment before the session is registered, and it was refused as "no sandbox is running". Docker
then waited, or came up with a TTY of its own choosing. A TUI drawing for a box it does not have
scrolls on every spinner tick instead of overwriting its last frame: the same endless scroll,
from a second direction, on the next Run or restart.

Terminal input that arrives while a start is in flight is now held and delivered the moment the
session registers. It is capped at 64 KiB, cleared when a start begins (so an old terminal's
answer is never typed into a new session), and dropped when the start ends without one.

## Stop means stopped

A terminal write used to hold the session map for its whole duration. A PTY whose reader has
stopped accepting input — which is exactly what a wedged `docker run` looks like — blocked that
write, and Stop and Resize waited behind the same lock. The button said "Stopping…" and nothing
moved, while the terminal kept drawing.

The write now takes the map only long enough to clone the input handle, and writes with no map
lock held. The container teardown is also bounded to fifteen seconds per step instead of the full
command timeout: a removal the daemon refuses is residue the sweep collects, and two minutes of
nothing on the Stop button is worse than a later cleanup.

## Upgrading

No image rebuild is needed for these fixes; the app updates itself from this release. If a stored
terminal size from 0.1.13 looks wrong after the update, resizing the window once replaces it, and
**Stop** is now bounded even if Docker is the thing that is slow.
